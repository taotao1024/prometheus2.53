# Prometheus storage 目录结构说明

> 基于 Prometheus v2.53 源码整理。
> `storage/` 是 Prometheus 的**存储抽象层**：定义统一的读写接口（`storage.Storage` / `Appender` / `Querier`），
> 并提供「多后端扇出写入 + 合并查询」的实现，以及**远程读写（remote write / remote read）**的完整实现。
> 它位于 `tsdb/`（本地存储引擎）之上，向上服务于 PromQL 引擎、抓取管理器、规则管理器与 HTTP API。

## 一、整体架构（数据流）

```
写入路径：
  scrape manager ─┐
  rule manager   ─┼─► fanoutStorage.Appender()   （fanout.go）
  remote write   ─┘        │
  接收端                    ├──► localStorage (tsdb.DB)   → Head + WAL + Block
                           └──► remoteStorage (remote/write.go)
                                     │  WriteStorage 的 WAL（queue_manager 保证重试/持久化）
                                     ▼
                                QueueManager（每个 remote_write 目标一条队列）
                                     │  分片 + 批量 + 重试（ewma.go 动态分片）
                                     ▼
                                远端接收方（Prometheus/Thanos/Mimir/...）

读取路径：
  PromQL 引擎 / HTTP API ─► fanoutStorage.Querier(mint, maxt)
                              │  merge.go：按标签合并多个 querier 的结果
                              ├──► 本地 TSDB 各 Block + Head
                              └──► remoteStorage.Querier()  （remote read 客户端，按需拉取远端）
```

## 二、目录结构总览

```
storage/
├── interface.go            # ★ 核心：所有存储接口与错误定义（Storage/Appender/Querier/...）
├── fanout.go               # ★ 扇出存储：写多份、读合并（Prometheus 的「Storage」实体）
├── merge.go                # ★ 查询结果合并器（按标签合并多个 SeriesSet）
├── generic.go              # 泛型查询抽象层（Querier 与 ChunkQuerier 共用逻辑）
├── secondary.go            # 次级查询器包装：错误降级为 warning（best effort）
├── buffer.go               # BufferedSeriesIterator：带回溯缓冲的迭代器
├── memoized_iterator.go    # MemoizedSeriesIterator：缓存上一个样本的迭代器
├── series.go               # Series 辅助结构：由样本列表/Chunk 构造 Series、格式转换
├── lazy.go                 # 惰性初始化的 SeriesSet 及空/错误 SeriesSet 实现
├── noop.go                 # 空实现（NoopQuerier 等），用于占位
├── errors.go               # 重复样本错误类型（含时间戳/值的详细报错）
├── *_test.go               # 各文件对应单元测试与基准
│
└── remote/                 # ★ 远程存储（remote write / remote read）完整实现
    ├── storage.go          # remote.Storage：聚合远程读客户端 + 挂载 WriteStorage
    ├── write.go            # WriteStorage：远端写目标管理、Appender 实现、WAL 生命周期
    ├── queue_manager.go    # QueueManager：每个目标的发送队列（分片、批量、重试、限流）
    ├── client.go           # 远程写 HTTP 客户端（协议 v1/v2、签名、超时、压缩）
    ├── codec.go            # 远程写请求/响应的编解码（protobuf framing）
    ├── chunked.go          # 「chunked」远程读协议实现（按 chunk 流式读取）
    ├── read.go             # 远程读客户端（sampleAndChunkQueryableClient、querier）
    ├── read_handler.go     # 远程读服务端 HTTP Handler（/api/v1/read）
    ├── write_handler.go    # 远程写服务端 HTTP Handler（/api/v1/write、OTLP）
    ├── ewma.go             # EWMA 指数滑动平均，用于动态调整写队列分片数
    ├── max_timestamp.go    # 各目标已发送最大时间戳跟踪（避免乱序/回退）
    ├── metadata_watcher.go # 监听元数据变更并通知远端
    ├── intern.go           # 字符串驻留（intern）优化，降低远程写内存分配
    ├── azuread/            # Azure AD OAuth2 认证（remote write 的 azuread 配置）
    └── otlptranslator/     # OTLP 指标 → Prometheus 指标名/标签的翻译规则
```

## 三、顶层文件功能说明

| 文件 | 功能 |
|------|------|
| `interface.go` | **整个存储层的契约**。定义 `Storage`（`Appendable` + `SampleAndChunkQueryable` + `StartTime` + `Close`）、`Appender`（`Append`/`Commit`/`Rollback` + exemplar/histogram/metadata/CT 扩展）、`Querier`、`ChunkQuerier`、`LabelQuerier`、`ExemplarQuerier`、`SeriesSet`/`ChunkSeriesSet`、`SelectHints`（查询提示：步长、聚合、分片等），以及所有写入错误（`ErrOutOfOrderSample`、`ErrOutOfBounds`、`ErrDuplicateSampleForTimestamp` 等）和测试桩（`MockQuerier`、`MockSeries`） |
| `fanout.go` | **扇出存储**：`NewFanout()` 包装多个 `Storage`。写入时把样本同时写入**所有** primary 存储（本地 TSDB + remote write 队列）；查询时把所有 primary 与 secondary 存储结果合并。`fanout` 类型即 Prometheus main 中使用的 `storage.Storage` 实体，并对不同存储的错误做聚合/忽略处理 |
| `merge.go` | **查询结果合并**：`mergeGenericQuerier` 按标签把多个 `SeriesSet` 归并（去重、按标签排序、合并 chunk），实现 primary/secondary 查询器的合并语义 |
| `generic.go` | **泛型查询抽象**：把 `Querier`/`ChunkQuerier` 抽象为统一的 `genericQuerier`（`genericSeriesSet`、`genericSeries` 等），让 merge/secondary/lazy 等逻辑只写一份，适配样本与 chunk 两种查询形态 |
| `secondary.go` | **次级查询器包装**：把某个 querier 变成「尽力而为」模式——除 `Close` 外的错误一律转成 **warning** 而不是让整个查询失败（用于 remote read 等不可靠后端） |
| `buffer.go` | `BufferedSeriesIterator`：在迭代器外增加回溯缓冲，支持 PromQL 中 range 查询的回看需求（如 `rate()` 需要前一个样本） |
| `memoized_iterator.go` | `MemoizedSeriesIterator`：缓存上一个返回的样本，供需要 delta/前值计算的场景使用；整数直方图统一按浮点直方图处理 |
| `series.go` | Series 构造与转换工具：`SeriesEntry`、`ChunkSeriesEntry`、由样本列表构造 Series（`NewListSeries`）、`NewSeriesSetFromChunkSeriesSet`、`NewSeriesSetToChunkSet`、`NewSeriesToChunkEncoder`（把样本编码为 chunk） |
| `lazy.go` | `lazyGenericSeriesSet`：首次调用 `Next()` 时才真正初始化数据源；另有 `warningsOnlySeriesSet`、`errorOnlySeriesSet` 用于只携带 warning/error 的结果 |
| `noop.go` | 空实现：`NoopQuerier` 等，用于禁用查询或测试占位 |
| `errors.go` | 重复样本错误的详细类型（`errDuplicateSampleForTimestamp`）：报错时携带时间戳、旧值/新值，便于排查 |

## 四、`remote/` 子目录功能说明

| 文件 | 功能 |
|------|------|
| `storage.go` | `remote.Storage`：聚合所有 `remote_read` 客户端（提供 `Querier`/`ChunkQuerier`，通过 `MergeQuerier` 合并），并把 `WriteStorage` 的 `Appender` 暴露出去；`StartTime()` 取本地存储起始时间用于 WAL 清理 |
| `write.go` | `WriteStorage`：解析 `remote_write` 配置、为每个目标创建/更新 `QueueManager`、实现 `Appender`（把样本写入远端写 WAL）、`LowestSentTimestamp()` 用于本地 WAL 截断保护、优雅关闭时 flush |
| `queue_manager.go` | **远程写核心**：每个目标一条持久化队列（基于 WAL）。负责样本入队、按 shard 并发发送、批量打包、重试与退避、`max_samples_per_send`/`max_shards`/`min_shards`/`capacity` 等参数、发送指标（`prometheus_remote_storage_*`） |
| `client.go` | 远程写 HTTP 客户端：协议 1.0/2.0、请求压缩（snappy/zstd）、自定义 Header、TLS/OAuth2/基本认证、响应解析与可重试状态码判断 |
| `codec.go` | 远程写请求的 protobuf 编码/解码（`prompb.WriteRequest`、framing、符号表等） |
| `read.go` | 远程**读**客户端：`sampleAndChunkQueryableClient`（按需向远端拉数据，且本地能覆盖的时间段直接返回 noop 避免远程请求）、`querier` 实现 `storage.Querier` |
| `read_handler.go` | 远程读**服务端** Handler（`/api/v1/read`）：解析远端请求的 matchers/时间段、限制并发与样本数、按 frame 流式返回 |
| `write_handler.go` | 远程写**服务端** Handler（`/api/v1/write`）与 **OTLP** Handler（`/api/v1/otlp/v1/metrics`）：解码请求 → 构造 Appender 写入本地存储 |
| `chunked.go` | 远程读的「chunked」格式实现：整块 chunk 传输，比逐样本更快 |
| `ewma.go` | 指数加权移动平均（EWMA）工具，用发送速率/积压动态调整队列 shard 数量 |
| `max_timestamp.go` | 记录每个 remote write 目标已发送的最大时间戳，防止跨队列乱序并支持 WAL watcher 追赶 |
| `metadata_watcher.go` | 监听元数据（metric type/help/unit）变更并推送给远端 |
| `intern.go` | 远程写样本字符串驻留池，减少重复 label 名的内存分配 |
| `azuread/` | Azure AD OAuth2 认证实现（`remote_write.azuread` 配置使用） |
| `otlptranslator/` | OTLP → Prometheus 转换：指标名/标签规范化（`AddMetricSuffixes`、命名空间、`.`/`-` 转 `_` 等） |

## 五、归属

- **归属服务**：Prometheus 服务端的**存储抽象层**，随 `prometheus` 二进制运行；不是独立服务、无独立端口。
  - 向上：PromQL 引擎、抓取管理器（scrape）、规则管理器（rules）、HTTP API（`/api/v1/*`）都只依赖本包定义的接口；
  - 向下：`tsdb/`（本地存储引擎）与各远端存储；
- `remote/` 的 Handler（`write_handler.go`、`read_handler.go`）虽由 Prometheus 进程提供，但承载的是**远端 Prometheus 访问本实例**的入口；
- 本包同样被 Thanos、Mimir、Cortex 等外部项目作为库引用（实现自己的 `storage.Storage`）。

## 六、访问入口

### 1. 进程内代码入口（`cmd/prometheus/main.go`）

```go
// 1. 创建本地 + 远程存储，并扇出组合
remoteStorage = remote.NewStorage(logger, registerer, localStorage.StartTime,
                                  localStoragePath, remoteFlushDeadline, scraper)   // main.go:709
fanoutStorage = storage.NewFanout(logger, localStorage, remoteStorage)               // main.go:710

// 2. 各个消费方都使用 fanoutStorage
//    scrape manager : fanoutStorage.Appender(ctx)   → 同时写本地 TSDB 与 remote write 队列
//    rule manager   : 同上（记录规则结果）
//    queryEngine    : fanoutStorage.Querier(mint, maxt) → 合并本地与 remote read 结果
//    web/api        : 同一份 fanoutStorage
```

### 2. 配置入口（`prometheus.yml`）

```yaml
remote_write:
  - url: http://remote:9090/api/v1/write   # 远程写目标（可多个）
    queue_config:                          # 对应 queue_manager.go 参数
      capacity: 10000
      max_shards: 200
      max_samples_per_send: 2000
      batch_send_deadline: 5s
      min_backoff: 30ms
      max_backoff: 5s
    write_relabel_configs: [...]           # 发送前的 relabel

remote_read:
  - url: http://remote:9090/api/v1/read    # 远程读目标（可多个）
    read_recent: true                      # 是否也读最近数据（否则本地可覆盖的时间段不发请求）
    required_matchers: {...}
```

启动 flag：`--storage.tsdb.path`（remote write 的 WAL 目录位于该路径下 `wal/`）、
`--storage.remote.flush-deadline`、`--enable-feature=remote-write-receiver`、
`--enable-feature=otlp-write-receiver`。

### 3. HTTP 接口入口

| 接口 | 说明 | 对应代码 |
|------|------|----------|
| `POST /api/v1/write` | **远程写接收端**（需 `--enable-feature=remote-write-receiver`）：其他 Prometheus/Agent 把样本推送进来 | `remote.NewWriteHandler()` |
| `POST /api/v1/otlp/v1/metrics` | **OTLP 接收端**（需 `--enable-feature=otlp-write-receiver`）：接收 OpenTelemetry 指标 | `remote.NewOTLPWriteHandler()` |
| `POST /api/v1/read` | **远程读服务端**：响应其他 Prometheus 的 remote read 请求 | `remote.NewReadHandler()` |
| `GET /api/v1/query`、`/api/v1/query_range`、`/api/v1/series`、`/api/v1/labels`、`/api/v1/label/<name>/values` | 查询接口，内部走 `fanoutStorage.Querier()` | `web/api/v1/api.go` |

> 出口方向（本实例主动访问远端）由 `remote_write` / `remote_read` 配置决定。

### 4. 可观测入口

| 入口 | 内容 |
|------|------|
| `GET /metrics` | `prometheus_remote_storage_*`（队列积压 `samples_pending`、`samples_total`、`failed_samples_total`、`shards`、`send_loop_duration_seconds`、`bytes_total` 等）、`prometheus_remote_storage_queue_highest_sent_timestamp_seconds` 等 |
| Web UI「Status → Runtime & Build Information」 | 无直接面板；remote write 队列状态主要通过上面的指标观察 |

## 七、关键实现要点

| 关注点 | 说明 | 相关文件 |
|--------|------|----------|
| 写入一致性 | `fanout` 会向所有 primary 存储写入；某个后端出错时按策略聚合错误（例如本地成功、远端失败不阻断抓取，但计入指标） | `fanout.go` |
| 远程写可靠性 | 样本先落**远端写 WAL**，再由 QueueManager 消费，进程重启后可继续发送 | `write.go`、`queue_manager.go` |
| 本地 WAL 清理保护 | `LowestSentTimestamp()` 保证本地 TSDB 不会在远端还没发出去的时候就截断 WAL | `write.go`、`remote/storage.go` |
| 远程读按需拉取 | 若查询时间段可被本地数据完全覆盖，则不请求远端（`preferLocalStorage`） | `read.go` |
| 错误降级 | secondary querier 把远端错误转 warning，避免单个远端故障导致整个查询失败 | `secondary.go` |
| 动态分片 | 依据 EWMA 的发送速率与积压动态调整 shard 数（`min_shards` ~ `max_shards`） | `ewma.go`、`queue_manager.go` |
