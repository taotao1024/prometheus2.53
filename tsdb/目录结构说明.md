# Prometheus TSDB 目录结构说明

> 基于 Prometheus v2.53 源码整理。
> `tsdb/` 是 Prometheus 的**时序数据库存储引擎**（Time Series DataBase library），
> 负责所有 Prometheus v2 数据的**存储与查询**。它既作为 `prometheus` 二进制的存储层，
> 也可作为独立 Go 库被外部项目（Thanos、Mimir、Cortex 等）引用。
>
> 相关文档：`tsdb/README.md`、`tsdb/docs/format/`（磁盘数据格式）、`tsdb/docs/usage.md`。

## 一、整体架构（数据流）

```
写入路径：
  scrape manager / remote write 接收端
        │  Appender(ctx)                          WAL (wlog/)
        ▼                                             │
  ┌─────────────┐   head_append.go   ┌──────────────┐▼──────────┐
  │  Head 内存块 │ ────────────────► │ WAL / mmap    │           │
  │  (head.go)   │                   │ chunk 段落盘   │ (chunks/) │
  └──────┬──────┘                    └──────────────┴───────────┘
         │  Compact() 定期截断为块 (compact.go)
         ▼
  ┌──────────────────┐   index/ 索引 + chunkenc/chunks 数据
  │ 持久化 Block (2h) │ ◄───────────  block.go / index/
  └──────┬──────────┘
         │  Compact 垂直/水平合并 → 按保留策略删除
         ▼
      data/<ULID>/ 块目录
      （重启时通过 head_wal.go 回放 WAL 恢复 Head）

查询路径：
  PromQL 引擎 → DB.Querier / ChunkQuerier / ExemplarQuerier (db.go, querier.go)
              → 合并 Head + 各持久化 Block 的查询结果
```

## 三、核心文件功能说明

| 文件 | 功能 |
|------|------|
| `db.go` | **TSDB 主入口**。`DB` 结构体与 `Open()` 构造函数（加载磁盘块、回放 WAL、启动后台 compaction）；实现 `storage.Storage` 接口：`Querier()` / `ChunkQuerier()` / `ExemplarQuerier()` / `Appender()`；另有 `Compact()`、`Snapshot()`、`Delete()`、`CleanTombstones()`、`reload()`、`Close()` 等生命周期管理方法 |
| `head.go` | **内存 Head 块**：所有最新（未压缩）数据所在，定义 `Head` 结构体、`HeadStats`、`WALReplayStatus`；管理 series 唯一化、minTime/maxTime、mmap chunk 引用等 |
| `head_append.go` | Head 的写入路径：`Appender` 的 `Append` / `AppendHistogram` / `AppendExemplar` / `UpdateMetadata` / `Commit` / `Rollback` 实现 |
| `head_read.go` | Head 的查询路径：提供 `Querier` / `ChunkQuerier`，支持读取 mmap 到磁盘的 chunk |
| `head_wal.go` | Head 与 WAL 的交互：启动时 **WAL 回放恢复内存状态**、WAL Checkpoint 生成与清理、按频率截断 WAL |
| `ooo_head.go` / `ooo_head_read.go` / `ooo_isolation.go` | **乱序样本支持**（`--storage.tsdb.out-of-order-time-window`）：独立的 OOO Head 写入、查询与事务隔离实现 |
| `block.go` | **持久化 Block**：`Block` 接口与磁盘块实现（`OpenBlock()`）。一个块 = 一段时间范围的数据（默认 2h），目录含 `meta.json`、`index`、`chunks/`、`tombstones` |
| `blockwriter.go` | `BlockWriter`：将样本流写成一个完整磁盘块的辅助器（供 `CreateBlock` / promtool 历史数据回填使用） |
| `compact.go` | **压缩合并**：`Compactor` 接口与 `LeveledCompactor` 实现——相邻小块合并为大块（垂直合并）、Head 截断为块；`ExponentialBlockRanges` 定义块时间跨度等级（2h → … → 保留期的 10%） |
| `querier.go` | 查询器实现：`blockQuerier` 等对单个块/Head 的查询，配合 `storage` 包的合并查询器向上提供统一接口 |
| `exemplar.go` | Exemplar 存储：环形缓冲实现、按时间范围查询（`--enable-feature=exemplar-storage` 开启） |
| `isolation.go` | 写入隔离：跟踪未提交样本的时间范围，保证并发查询读不到未提交数据 |
| `repair.go` | 修复损坏的索引文件（重建 postings） |
| `tsdbblockutil.go` | `CreateBlock`：从样本序列创建磁盘块（promtool `tsdb create-blocks-from` 回填功能的基础） |

## 四、子目录功能说明

| 子目录 | 功能 |
|--------|------|
| `wlog/` | **WAL（预写日志）实现**：`WL` 写入器（分段文件、snappy/zstd 压缩）、`LiveReader` 回放、Checkpoint 生成与清理；掉电/重启后靠它恢复 Head 数据 |
| `agent/` | **Agent 模式 TSDB**（`--enable-feature=agent`）：只有 WAL 没有 Block，样本写入 WAL 后经 remote storage 转发远端；按 `TruncateFrequency` / `MinWALTime` / `MaxWALTime` 截断；入口 `agent.Open()`；不支持查询与 exemplar |
| `index/` | **索引文件格式**：符号表（symbols）、倒排索引（postings）、series 区块的编码/解码与迭代器，对应块目录中的 `index` 文件 |
| `chunks/` | **Head chunk 磁盘段**：`ChunkDiskMapper` 将 Head 中的 chunk 顺序写入 `chunks_head/` 段文件并用 mmap 读取，避免全部驻留内存 |
| `chunkenc/` | **chunk 编码器**：Gorilla XOR 浮点压缩、直方图/浮点直方图编码、varbit 编码、`Pool`（chunk 内存池） |
| `record/` | **WAL/mmap 记录编解码**：`RefSeries`、`RefSample`、`RefExemplar`、`RefMetadata`、`RefHistogramSample`、`RefMmapMarker` 等记录类型与 `Encoder` / `Decoder` |
| `tombstones/` | **墓碑**：记录被删除的时间范围（`DeleteMRange`），查询时过滤、compaction 时真正清除；持久化为块目录中的 `tombstones` 文件 |
| `encoding/` | 底层编码原语：`bstream` 位流、varint、zigzag、浮点字节序工具（被 chunkenc / index / record 复用） |
| `fileutil/` | 文件系统工具：原子 rename、目录 fsync、文件替换等，保证块目录操作的崩溃一致性 |
| `errors/` | TSDB 错误类型封装：区分可重试与不可重试错误，供 remote write 等上层判断 |
| `goversion/` | Go 版本比较工具（用于按运行环境 Go 版本做行为判断） |
| `tsdbutil/` | 测试辅助：构造 sample / chunk / histogram 的工具函数、目录锁测试工具 |
| `testdata/` | 测试数据 |
| `docs/` | 设计文档：`format/`（**磁盘数据格式**：块目录结构、index、chunks、tombstones、WAL、mmap 文件）、`usage.md`（作为库使用）、`bstream.md`、`refs.md` |

## 五、归属

- **归属服务**：Prometheus 服务端存储层，随 `prometheus` 二进制运行，不是独立服务（无自有端口）；
  - **Server 模式**：完整 TSDB（Head + WAL + Block + Compaction + 保留策略）；
  - **Agent 模式**（`--enable-feature=agent`）：仅 `tsdb/agent/`（WAL-only，不落块、不查询）；
- 同一库也被 **promtool** CLI 工具和外部项目（Thanos / Mimir / Cortex）作为 Go 库使用。

## 六、访问入口

### 1. 进程内代码入口

```go
// cmd/prometheus/main.go —— openDBWithMetrics()
db, err := tsdb.Open(localStoragePath, logger, registerer, &opts, stats) // tsdb/db.go:734
localStorage.Set(db, startTimeMargin) // 包装为 readyStorage 供全进程使用
```

使用方（均通过 `storage.Storage` / `storage.Appender` / `storage.Querier` 接口）：

| 消费方 | 方向 | 说明 |
|--------|------|------|
| scrape manager | 写 | 抓取样本 → `fanoutStorage.Appender()` → Head + WAL |
| remote write 接收端 | 写 | `--enable-feature=remote-write-receiver` 时同样走 Appender |
| rule manager | 写/读 | 记录规则结果写入、规则评估查询 |
| PromQL 引擎 | 读 | `DB.Querier()` / `ChunkQuerier()` 提供数据 |
| remote storage | 协同 | `db.SetWriteNotified(remoteStorage)`：WAL 写入通知远端转发（Agent 模式核心链路） |

### 2. 配置入口（启动 flag）

```bash
./prometheus \
  --storage.tsdb.path=data/ \                # 数据目录（默认 data/）
  --storage.tsdb.retention.time=15d \        # 时间保留策略（默认 15d）
  --storage.tsdb.retention.size=512MB \      # 大小保留策略
  --storage.tsdb.min-block-duration=2h \     # 块跨度（测试用）
  --storage.tsdb.no-lockfile \
  --storage.tsdb.wal-compression
```

> Agent 模式对应 `--storage.agent.*` 系列 flag（见 `tsdb/agent/`）。

### 3. HTTP 管理入口（需 `--web.enable-admin-api`）

| API | 对应 TSDB 方法 |
|-----|----------------|
| `POST /api/v1/admin/tsdb/snapshot` | `DB.Snapshot(dir, withHead)` |
| `POST /api/v1/admin/tsdb/delete_series` | `DB.Delete(ctx, mint, maxt, matchers)` |
| `POST /api/v1/admin/tsdb/clean_tombstones` | `DB.CleanTombstones()` |

### 4. CLI 入口（promtool）

```bash
promtool tsdb analyze <block dir>            # 分析块的统计信息
promtool tsdb list <data dir>                # 列出所有块
promtool tsdb dump --sandbox-dir-root ...    # 导出原始样本
promtool tsdb bench write ...                # 写入基准测试
promtool tsdb create-blocks-from openmetrics # OpenMetrics 历史数据回填（走 CreateBlock）
```

### 5. 磁盘数据入口

```text
--storage.tsdb.path/
├── wal/                  # WAL 段文件（wlog/ 管理）
├── chunks_head/          # Head chunk mmap 段文件（chunks/ 管理）
├── wal_checkpoint.*/     # WAL Checkpoint（head_wal.go 生成）
└── <ULID>/               # 持久化块（block.go 打开）
    ├── meta.json         # 块元数据（时间范围、统计、compaction 来源）
    ├── index             # 索引文件（index/ 格式）
    ├── chunks/           # chunk 数据文件
    └── tombstones        # 删除标记（tombstones/ 格式）
```

### 6. 可观测入口

| 入口 | 内容 |
|------|------|
| `GET /metrics` | `prometheus_tsdb_*` 指标（head series 数、WAL 相关、compaction、查询等） |
| Web UI 启动页 | TSDB 未就绪时显示 WAL 回放进度（`WALReplayStatus`，经 `readyStorage.WALReplayStatus()` 暴露给 `/api/v1/status/tsdb` 等） |
| `prometheus_tsdb_lowest_timestamp_seconds` 等 | `cmd/prometheus/main.go` 中 `openDBWithMetrics` 额外注册的指标 |

## 七、关键配置与功能的对应关系

| 功能 | 配置/开关 | 相关代码 |
|------|-----------|----------|
| 乱序样本写入 | `--storage.tsdb.out-of-order-time-window`（或配置文件 `tsdb.out_of_order_time_window`） | `ooo_head*.go` |
| Exemplar 存储 | `--enable-feature=exemplar-storage` + `storage.exemplars.max_exemplars` | `exemplar.go` |
| 内存快照关停 | `--enable-feature=memory-snapshot-on-shutdown` | `head_wal.go` |
| Agent 模式 | `--enable-feature=agent` + `--storage.agent.*` | `agent/` |
| native histogram | `--enable-feature=native-histograms` | `chunkenc/`、`head_append.go` |
