# Prometheus model 目录结构说明

> 基于 Prometheus v2.53 源码整理。
> `model/` 是 Prometheus 的**核心数据模型与基础算法包**：定义整个生态共享的数据结构
> （标签 `labels`、exemplar、原生直方图 `histogram`、指标元数据 `metadata`）、
> 核心算法（relabel、文本解析 `textparse`、规则文件格式 `rulefmt`、时间戳、staleness 值）。
> 它**不是服务、无端口、无配置**，是被所有组件（tsdb、promql、scrape、storage、web…）
> 广泛引用的最底层依赖。

## 一、定位说明

```
model/（9 个独立子包）
  ├── 数据结构：labels（★ 标签）、exemplar、histogram（★ 原生直方图）、metadata
  ├── 解析/校验：textparse（★ 指标暴露格式解析）、rulefmt（★ 规则文件格式）、relabel（★ 重标）
  └── 基础工具：timestamp（毫秒时间戳）、value（staleness 特殊值）
```

- 各子包职责单一、可独立引用，是 Prometheus 与外部生态（Thanos/Cortex/各 SDK）的**共同数据契约**；
- 与 `prompb/`（线格式）互补：`model` 是内存模型，`prompb` 是传输格式。

## 二、目录结构总览

```
model/
├── labels/       # ★ 标签集 Labels：三种存储实现（build tag 切换）、Matcher、正则引擎
├── histogram/    # ★ 原生直方图：Histogram/FloatHistogram/Span/桶迭代器/合并运算
├── relabel/      # ★ 重标（relabel）：Action、Config(YAML)、Process/ProcessBuilder
├── textparse/    # ★ 指标暴露格式解析：Prometheus text / OpenMetrics / Protobuf（ragel 词法）
├── rulefmt/      # ★ 规则文件格式：RuleGroups 解析与校验（YAML）
├── exemplar/     # Exemplar 数据结构
├── metadata/     # 指标元数据（type/help/unit）
├── timestamp/    # 毫秒精度时间戳转换
└── value/        # 特殊值常量（StaleNaN）与判断
```

## 三、各子包功能说明

### 3.1 `labels/` —— 标签集（最核心的模型）

| 文件 | 作用 |
|------|------|
| `labels.go` | 默认实现（slice 存储）：`Labels []Label`（按名称有序）、`Label{Name, Value}`、`Equal/Compare/New/FromStrings`、`Builder`（增量修改）、`ScratchBuilder`（高性能构建）、`SymbolTable`（dedupelabels 下有实现，默认为空壳） |
| `labels_stringlabels.go` | build tag `stringlabels`：把整个标签集编码为一个 string，内存最省（官方发行版用于减小 GC 压力） |
| `labels_dedupelabels.go` | build tag `dedupelabels`：带全局符号表的去重实现（字符串驻留） |
| `labels_common.go` | 三种实现共享的常量与工具（`MetricName`、保留标签 `__name__` 等） |
| `matcher.go` | `Matcher` 标签匹配器：`=`, `!=`, `=~`, `!~` 四种类型（PromQL 选择器与 relabel 的基础） |
| `regexp.go` | 自定义正则引擎 `fastRegexMatcher`：对常见锚定模式（`^xxx$`、前缀/后缀/完全匹配）做**非正则快速路径**，慢路径才回落 `regexp` |
| `sharding*.go` | 按 build tag 提供 `LabelHash`/`SeriesHash`（dedupelabels 用符号表哈希，其余用 FNV） |
| `test_utils.go` | 测试构造工具 |

> 关键点：三种实现行为一致，编译期用 build tag 选择；**所有组件间传递的标签都是这个包的类型**。

### 3.2 `histogram/` —— 原生直方图（NHCB 之前的核心表示）

| 文件 | 作用 |
|------|------|
| `histogram.go` | 整数计数直方图 `Histogram`：`Schema`（桶宽指数）、`ZeroThreshold`/`ZeroCount`（零桶）、`PositiveSpans/PositiveBuckets`、`NegativeSpans/NegativeBuckets`、`CounterResetHint`（counter/gauge/未知/重置标记）；`Span` 描述桶索引布局（稀疏存储） |
| `float_histogram.go` | 浮点计数版 `FloatHistogram`：`Mul/Div/Add/Sub/Copy/CopyTo/Compact`、检测 counter reset（`detectReset`）、正/反/全量桶迭代器（`floatBucketIterator` 等）、分辨率降级 |
| `generic.go` | 跨类型的通用算法：桶边界 `getBound`、span 校验、`ReduceResolution`、通用迭代器接口（`BucketCount`/`InternalBucketCount`） |
| `test_utils.go` | 测试用直方图生成器 |

> 主要使用方：`tsdb`（存储编码）、`promql`（`histogram_quantile` 等函数）、`prompb`（线格式字段）、`scrape`（protobuf 解析）、`textparse`。

### 3.3 `relabel/` —— 重标引擎

| 元素 | 作用 |
|------|------|
| `Action` | 全部动作：`replace`、`keep`、`drop`、`hashmod`、`labelmap`、`labeldrop`、`labelkeep`、`keepequal`、`dropequal`、`lowercase`、`uppercase` |
| `Config` | 单条 relabel 规则的 YAML 模型（`source_labels`/`separator`/`target_label`/`regex`/`modulus`/`replacement`/`action`），被 `scrape_configs`、`alertmanager_configs`、`remote_write`、各 SD 引用 |
| `Regexp` / `NewRegexp` | 带快速路径的正则封装（复用 `labels/regexp.go` 思想；`MustNewRegexp` panic 版） |
| `Process(lbls, cfgs...)` | 顺序应用规则，返回 `(新标签集, keep)`——不可变版本 |
| `ProcessBuilder(lb, cfgs...)` | 基于 `labels.Builder` 的可变版本（scrape/notifier 内部使用） |

> 使用方：`scrape`（目标 relabel + metric relabel）、`notifier`（告警 relabel）、`discovery`（SD 目标过滤）、`config`（YAML）、`promtool`（check 脱敏）。

### 3.4 `textparse/` —— 指标暴露格式解析器

| 文件 | 作用 |
|------|------|
| `interface.go` | `Parser` 接口（`Next/Metric/Labels/Sample/Exemplar/Histogram/Help/Type/Metadata...`）、`Entry` 枚举、**工厂 `New(b, contentType, parseClassicHistograms, st)`**——按 `Content-Type` 选择解析器 |
| `promparse.go` | Prometheus 文本格式解析器 `PromParser`（含 `promlexer`：ragel 生成的词法分析） |
| `openmetricsparse.go` | OpenMetrics 解析器 `OpenMetricsParser`（`# EOF`、状态信息、UTF-8 引号标签名等） |
| `protobufparse.go` | Protobuf 暴露格式解析器 `ProtobufParser`（MetricFamily dto；支持经典直方图转原生直方图 `isNativeHistogram`） |
| `promlexer.l` / `openmetricslexer.l` | ragel 词法规则源文件，构建时生成 `promlexer.go` 等 |
| `promtestdata.txt` 等测试数据、`README.md` | 格式说明与测试样例 |

> 使用方：`scrape/scrape.go`（`Content-Type` 协商后调 `textparse.New`）、`promtool`。

### 3.5 `rulefmt/` —— 规则文件格式

| 元素 | 作用 |
|------|------|
| `RuleGroups` / `RuleGroup` / `RuleNode` | 规则文件的 YAML 模型（`groups: [{name, interval, limit, rules: [...] }]`；`RuleNode` 用 `yaml.Node` 保留原始字段并区分 record/alert） |
| `Parse(content)` / `ParseFile(file)` | 解析 + 全量校验：语法、必填字段、重复组名/规则名、表达式可解析、**模板可渲染**（`testTemplateParsing` 调 `template` 的 ParseTest） |
| `Error` / `WrappedError` | 结构化错误（带 position 行列信息，输出 `file:line:col` 格式） |
| `testdata/*.yaml` | 13 个测试规则文件（合法/非法样例） |

> 使用方：`rules/manager.go`（`LoadGroups`）、`promtool check rules`。

### 3.6 其余子包

| 子包 | 内容 | 使用方 |
|------|------|--------|
| `exemplar` | `Exemplar{Labels, Value, Ts, HasTs}`、`QueryResult{SeriesLabels, Exemplars}`、`Compare` | `tsdb`（exemplar 存储）、`scrape`（解析 exemplar）、`promql`、`web/api`（`/query_exemplars`） |
| `metadata` | `Metadata{Type, MetricFamily, Help, Unit}` | `scrape`（目标级元数据缓存）、`web/api`（`/metadata`、`/targets/metadata`）、`prompb`（metadata 传输） |
| `timestamp` | `FromTime(t) int64`（毫秒）、`Time(ts)`、`FromFloatSeconds(f)` | 全仓库（TSDB 采样时间戳统一为毫秒 int64） |
| `value` | 特殊值常量：`StaleNaN`（staleness 标记 NaN 的位模式）与 `IsStaleNaN(v)`；其它特殊值常量 | `tsdb`、`scrape`、`storage`（staleness 语义的实现基础） |

## 四、归属

- **归属**：Prometheus 的**底层模型库**，不构成服务、无进程、无端口；是所有功能组件与外部生态（Thanos、Cortex/Mimir、各语言 client/SDK）的**共享数据契约层**。
- 典型消费关系：

| 组件 | 使用的 model 子包 |
|------|-------------------|
| `scrape` | `textparse`（解析暴露格式）、`labels`、`relabel`、`histogram`、`exemplar`、`metadata`、`timestamp` |
| `tsdb` | `labels`、`histogram`、`exemplar`、`timestamp`、`value` |
| `promql` / `promql/parser` | `labels`、`histogram`、`value`、`timestamp` |
| `storage` / `storage/remote` | `labels`、`exemplar`、`metadata`、`histogram`、`timestamp` |
| `rules` | `rulefmt`（加载规则文件）、`labels`、`timestamp` |
| `discovery` / `notifier` | `labels`、`relabel`（目标/告警重标）、`timestamp` |
| `web` / `web/api/v1` | `labels`（matcher 参数解析）、`exemplar`、`metadata` |
| `promtool` | `rulefmt`（check rules）、`textparse`、`relabel`（check config/SD） |

## 五、访问入口

### 1. 代码入口（唯一入口：import）

```go
import (
    "github.com/prometheus/prometheus/model/labels"      // 标签与匹配器
    "github.com/prometheus/prometheus/model/relabel"     // 重标
    "github.com/prometheus/prometheus/model/textparse"   // 暴露格式解析
    "github.com/prometheus/prometheus/model/rulefmt"     // 规则文件解析
    ...
)
```

**典型调用链**（抓取解析一条指标的全过程，几乎横跨整个 `model/`）：

```
scrape.scrapeLoop.scrape()
  → textparse.New(body, contentType, ...)        // 按 Content-Type 选 PromParser/OpenMetricsParser/ProtobufParser
  → parser.Labels(...)                           // 构造 labels.Labels（经 SymbolTable 驻留）
  → relabel.Process(metricRelabelConfigs)        // metric_relabel_configs 过滤/改写
  → app.Append(ref, lset, timestamp.FromTime(ts), value)  // value 为 StaleNaN 时写 staleness 标记
```

### 2. 用户可见入口（模型最终暴露的位置）

| 用户入口 | 背后的 model 子包 |
|----------|-------------------|
| PromQL 选择器 `{job=~"node.*"}` | `labels`（Matcher + 正则引擎） |
| `prometheus.yml` 的 `relabel_configs` / `metric_relabel_configs` | `relabel` |
| 被抓取方的 `/metrics`（text/OpenMetrics/Protobuf） | `textparse` |
| `rule_files` 的规则 YAML | `rulefmt` |
| `histogram_quantile()` 与原生直方图数据 | `histogram` |
| `/api/v1/query_exemplars`、exemplar 存储 | `exemplar` |
| `/api/v1/metadata`、`/targets/metadata` | `metadata` |
| 查询结果中样本消失（staleness） | `value`（StaleNaN） |

### 3. 构建期入口（labels 的实现选择）

```bash
go build                          # 默认 slice 实现（labels.go）
go build -tags stringlabels       # 字符串编码实现（省内存）
go build -tags dedupelabels       # 符号表去重实现（配合 textparse SymbolTable）
```

### 4. 代码生成入口

```bash
# textparse 的 ragel 词法分析器（.l → .go）
# 由仓库 Makefile 的 parser 相关目标处理（gofmt 前生成）
ragel -Z -G2 -o promlexer.go promlexer.l
```

## 六、注意事项

| 事项 | 说明 |
|------|------|
| `Labels` 必须有序 | `Labels` 按标签名排序是有序集合的**不变式**（二分查找的前提），构造时务必用 `New`/`ScratchBuilder.Sort` |
| build tag 互斥 | `stringlabels` 与 `dedupelabels` 不能同时启用；跨实现序列化行为一致 |
| `relabel.Process` 是不可变 API | 返回新标签集；热路径用 `ProcessBuilder` 避免分配 |
| `regex:` 是 RE2 语法 | relabel 的正则默认锚定（隐式 `^(?:...)$`）；`Regexp` 对常见锚定模式有快速路径 |
| OpenMetrics 与 text 差异 | OpenMetrics 支持 `# EOF`、`# UNIT`、引号 UTF-8 标签名；`textparse.New` 按 Content-Type 分派 |
| `StaleNaN` 是位模式 NaN | 不能与真实 NaN 混淆，只能通过 `value.IsStaleNaN` 判断，比较时用位模式 |
| `rulefmt.Parse` 做全量校验 | 除 YAML 语法外还校验表达式与模板，规则加载与 `promtool check rules` 共用此入口 |
| 时间戳统一毫秒 | `timestamp.FromTime` 截断到毫秒；全链路（TSDB/prompb/API）均为毫秒 int64 |
