# Prometheus util 目录结构说明

> 基于 Prometheus v2.53 源码整理。
> `util/` 是 Prometheus 的**通用工具库集合**：18 个互相独立的小型子包，
> 提供浮点比较、查询警告、CLI 文档生成、格式转换、并发闸门、HTTP 工具、JSON 编码、
> 日志中间件、对象池、查询统计、标签清洗、测试辅助等基础能力。
> 它**不是服务、无端口**，只是被 `prometheus` / `promtool` 各组件 import 的内部库
> （`github.com/prometheus/prometheus/util/...`）。

## 一、定位说明

```
util/（18 个独立子包，无顶层 Go 文件）
  ├── 服务运行时使用：annotations、gate、httputil、jsonutil、logging、pool、
  │                   runtime、stats、strutil、zeropool、almost、osutil、runutil、treecache
  ├── CLI / 文档使用：documentcli、fmtutil
  └── 仅测试使用：    teststorage、testutil
```

- 每个子包职责单一、互不依赖（避免循环引用），可独立引用；
- 命名规律：包名 = 功能（如 `pool` = 对象池，`gate` = 并发闸门）；
- 其中 `teststorage`、`testutil` 只应出现在测试代码中。

## 二、目录结构总览

```
util/
├── almost/          # 浮点数近似相等比较
├── annotations/     # ★ PromQL 查询警告（annotations）的模型与预定义警告
├── documentcli/     # kingpin CLI → Markdown 文档生成器
├── fmtutil/         # Prometheus 文本格式 → prompb.WriteRequest 转换
├── gate/            # 并发闸门（限流信号量）
├── httputil/        # HTTP 工具：gzip 压缩、CORS、路由路径注入
├── jsonutil/        # 基于 jsoniter 的流式 JSON 编码辅助
├── logging/         # 日志中间件：去重、限速、JSON 文件日志
├── osutil/          # 操作系统信息（FQDN）
├── pool/            # 按大小分级的字节池
├── runtime/         # 平台相关系统信息（文件描述符上限、statfs、uname）
├── runutil/         # 重试工具 Retry()
├── stats/           # ★ 查询统计（计时、逐 step 样本统计）
├── strutil/         # 字符串工具：反转义、标签名清洗、图表链接
├── teststorage/     # 测试用 TSDB 存储封装
├── testutil/        # 测试断言与辅助（临时目录、端口、HTTP mock 等）
├── treecache/       # ZooKeeper 树缓存
└── zeropool/        # 泛型对象池 Pool[T]
```

## 三、各子包功能说明

### 3.1 运行时工具

| 子包 | 关键导出 | 功能 | 主要使用方 |
|------|----------|------|-----------|
| `almost` | `Equal(a, b, epsilon float64) bool` | 判断两个浮点数是否在 `epsilon` 内近似相等（处理 denormal/极小值边界） | `promql/quantile.go`（分位数插值容差）、`promql/promqltest` |
| `annotations` | `Annotations map[string]error`；`New/Add/Merge/AsErrors/AsStrings`；预定义警告如 `NewInvalidQuantileWarning`、`NewBadBucketLabelWarning`、`NewMixedFloatsHistogramsWarning`、`NewMixedClassicNativeHistogramsWarning`、`NewNativeHistogramNotCounterWarning`、`NewPossibleNonCounterInfo`、`NewHistogramQuantileForcedMonotonicityInfo` 等 | **查询警告的统一模型**：PromQL 求值过程中产生的 warning/info 都收集为 `Annotations`，随查询结果返回给客户端（API 的 `warnings`/`infos` 字段） | `promql`（引擎与函数）、`storage`（接口签名）、`web/api/v1`（结果编码） |
| `gate` | `New(length int) *Gate`；`Start(ctx)` / `Done()` | **并发闸门**：限制同时进入临界区的 goroutine 数量，满时阻塞或随 ctx 取消 | `storage/remote/read_handler.go`（远程读并发上限） |
| `httputil` | `CompressionHandler`（gzip/deflate 响应压缩）、`SetCORS(w, o, r)`（CORS 头）、`ContextWithPath`/`ContextFromRequest`（把路由路径注入 ctx） | Web 服务的 HTTP 中间件工具 | `web/web.go` |
| `jsonutil` | `MarshalTimestamp(t, stream)`、`MarshalFloat(f, stream)`、`MarshalHistogram(h, stream)` | 基于 `jsoniter` 流式 API 的高性能 JSON 编码：时间戳、浮点数（`NaN`/`Inf` 特殊处理）、直方图 | `web/api/v1`（`/query` 等结果序列化） |
| `logging` | `Dedupe(next, repeat) *Deduper`（相同日志在窗口期内只输出一次）、`RateLimit(next, limit)`（日志限速）、`NewJSONFileLogger(path)`（JSON 行文件日志）、`NewJSONFileLogger` 配套 `Close()` | go-kit log 的装饰器集合 | `cmd/prometheus/main.go`（启动日志/日志文件）、`storage/remote/storage.go` |
| `osutil` | `GetFQDN() (string, error)` | 获取主机完整域名 | `scrape/manager.go` |
| `pool` | `New(minSize, maxSize, factor, makeFunc)`；`Get(sz)` / `Put(s)` | **按大小分级的 `sync.Pool`**：按 2 的幂等档位复用字节切片，避免大对象反复分配 | `scrape/scrape.go`（抓取响应 body 缓冲）、`scrape/manager.go` |
| `runtime` | `limits_*.go`（文件描述符上限 `GetLimits`，Windows/OpenBSD 有对应实现）、`statfs*.go`（磁盘空间 `Statfs`）、`uname_*.go`（内核信息） | 跨平台系统信息采集（按 GOOS 分文件编译） | `cmd/prometheus/main.go`（`/api/v1/status/runtimeinfo`：max open files、GOMAXPROCS、CWD 等） |
| `runutil` | `Retry(interval, stopc, f) error` | 固定间隔重试直到成功或 `stopc` 关闭/ctx 取消 | `storage/remote`、`tsdb`、各测试 |
| `stats` | `QueryTiming`（计时维度枚举）、`Timer`/`TimerGroup`/`SpanTimer`（计时器，可挂 Prometheus Observer）、`QuerySamples`（查询样本统计，支持 `InitStepTracking`/`IncrementSamplesAtStep` 逐 step 统计与峰值）、`QueryStats` 接口（`stats=perf` 时输出） | **查询性能统计框架**：PromQL 引擎在求值时记录各阶段耗时与样本扫描量 | `promql/engine.go`、`web/api/v1/api.go`（`/query` 的 `stats=all/perf` 参数） |
| `strutil` | `Unquote(s)`（标签值反转义）、`SanitizeLabelName(name)` / `SanitizeFullLabelName(name)`（非法字符替换为 `_`）、`TableLinkForExpression` / `GraphLinkForExpression`（生成 Web UI 控制台链接） | 字符串与标签清洗工具 | `rules/manager.go`、`template/template.go`、`web` |
| `treecache` | `NewZookeeperTreeCache(conn, path, events, logger)`；`ZookeeperTreeCacheEvent`；`Stop()` | **ZooKeeper 树缓存**：watch 整棵子树并把增删改事件发到 channel | `discovery/zookeeper/zookeeper.go`（ marathon/serverset SD 的数据源） |
| `zeropool` | `New[T any](item func() T) Pool[T]`；`Get()`/`Put(x)` | 泛型对象池：池空时返回零值（不强制构造），减少分配；比 `sync.Pool` 多 `Put` 去重语义 | `promql/engine.go`、`tsdb/head.go`、`tsdb/head_wal.go`、`tsdb/agent/db.go` |

### 3.2 CLI / 文档工具

| 子包 | 关键导出 | 功能 | 主要使用方 |
|------|----------|------|-----------|
| `documentcli` | `GenerateMarkdown(model *kingpin.ApplicationModel, writer)` | 把 kingpin 命令行模型渲染为 **Markdown 文档**（flag 表、参数表、子命令表，自动决定列） | `cmd/prometheus/main.go`、`cmd/promtool/main.go`（`--write-documentation` 等隐藏命令，生成 `docs/command-line/` 下的文档） |
| `fmtutil` | `MetricTextToWriteRequest(input, labels)`、`MetricFamiliesToWriteRequest(mf, extraLabels)`、`MetricMetadataTypeValue` | 把 **Prometheus 文本格式**或 protobuf `MetricFamily` 转换为 `prompb.WriteRequest`（补 extra labels、固定时间戳） | `cmd/promtool/metrics.go`（`promtool tsdb create-blocks-from` 系列的格式转换基础） |

### 3.3 测试辅助（仅供测试代码使用）

| 子包 | 关键导出 | 功能 | 主要使用方 |
|------|----------|------|-----------|
| `teststorage` | `New(t)` / `NewWithError()` → `*TestStorage`（实现 `storage.Storage`：Queryable/Appender/Exemplar） | 在临时目录打开一个真实 TSDB 供测试使用，`Close()` 自动清理 | `promql`、`rules`、`scrape`、`storage`、`web` 的测试 |
| `testutil` | `RequireEqual` / `RequireEqualWithOptions`（cmp 断言）、`MockContext`、`NewTemporaryDirectory` / `DirHash`、`NewLogger(t)`、`RandomUnprivilegedPort`、`NewRoundTripCheckRequest`（HTTP RoundTripper mock）、`TolerantVerifyLeak` | 全仓库通用的测试断言与脚手架 | `config`、`discovery`、`promql`、`rules`、`scrape`、`tsdb` 等几乎所有 `*_test.go` |

## 四、归属

- **归属**：Prometheus 的**内部工具库**，不属于任何单一服务；随 `prometheus` 与 `promtool` 两个二进制一起编译，但**本身无进程、无端口、无配置**。
- 消费关系总览：

| 组件 | 使用的 util 子包 |
|------|------------------|
| `web` / `web/api/v1` | `annotations`、`httputil`、`jsonutil`、`stats`、`strutil` |
| `promql` | `annotations`、`almost`、`stats`、`zeropool` |
| `storage` / `storage/remote` | `annotations`、`gate`、`logging`、`runutil` |
| `scrape` | `pool`、`osutil`、`runutil` |
| `tsdb` / `tsdb/agent` | `zeropool`、`runutil` |
| `discovery/zookeeper` | `treecache` |
| `rules` / `template` | `strutil` |
| `cmd/prometheus` | `documentcli`、`logging`、`runtime` |
| `cmd/promtool` | `documentcli`、`fmtutil` |
| 全部测试 | `teststorage`、`testutil` |

- 这些子包也被其他 Prometheus 生态项目（Thanos、Cortex/Mimir 等的历史 fork）复用或复制。

## 五、访问入口

### 1. 代码入口（唯一入口：import）

```go
import (
    "github.com/prometheus/prometheus/util/annotations"   // 查询警告
    "github.com/prometheus/prometheus/util/gate"          // 并发闸门
    "github.com/prometheus/prometheus/util/stats"         // 查询统计
    "github.com/prometheus/prometheus/util/testutil"      // 仅测试
    ...
)
```

典型调用链示例：

```
用户查询 /api/v1/query?stats=all
  → web/api/v1/api.go     使用 util/stats 构造 QueryStats
  → promql/engine.go      记录 util/stats 的 Timer / QuerySamples，warnings 写入 util/annotations
  → 结果经 util/jsonutil 的 MarshalFloat/MarshalTimestamp 流式编码返回
```

```
远程读请求进入 /api/v1/read
  → storage/remote/read_handler.go   使用 util/gate.New(concurrentReads) 限制并发
  → 每个请求 Gate.Start(ctx) … defer Gate.Done()
```

### 2. CLI 入口（documentcli 的产物入口）

```bash
prometheus --write-documentation > docs/command-line/prometheus.md   # 生成 CLI Markdown
promtool --write-documentation    > docs/command-line/promtool.md
```

### 3. 用户可见的功能入口（子包能力最终暴露的位置）

| 用户入口 | 背后的 util 子包 |
|----------|------------------|
| `GET /api/v1/query` 响应中的 `warnings` / `infos` 字段 | `annotations` |
| `GET /api/v1/query?stats=all` 的 `stats` 对象（耗时、逐 step 样本数） | `stats` |
| Web API 响应的 gzip 压缩与 CORS | `httputil` |
| `promtool tsdb create-blocks-from ...`（文本格式回填 TSDB） | `fmtutil` |
| `docs/command-line/*.md` CLI 文档 | `documentcli` |
| `/api/v1/status/runtimeinfo`（max open files 等） | `runtime` |
| `alerting_sd`/serverset 类 SD（ZooKeeper） | `treecache` |
| 测试（`go test ./...` 全仓库） | `teststorage`、`testutil` |

### 4. 无配置入口

`util/` 下没有任何启动 flag、配置段或环境变量；相关配置都在使用方组件中
（如远程读并发在 `remote_read` 段，查询统计由 `stats` 查询参数控制）。

## 六、注意事项

| 事项 | 说明 |
|------|------|
| 包间零依赖 | 子包之间互相不 import，保持可独立引用（新增依赖前先确认不形成环） |
| `teststorage`/`testutil` 勿进生产代码 | 二者 import `testing`，只能在 `*_test.go` 中使用 |
| `annotations` 是对外契约 | `Annotations` 的 key 会原样出现在 API 响应的 `warnings`/`infos` 中，增删警告需考虑 API 兼容 |
| 平台差异集中在 `runtime` | `limits_windows.go`、`vmlimits_openbsd.go`、`statfs_linux_386.go` 等按 GOOS/GOARCH 编译，改动需多平台验证 |
| `pool` vs `zeropool` | `pool` 是按容量分级的字节池（需 `Get(sz)`），`zeropool` 是泛型任意类型池（零值兜底），语义不同勿混用 |
| `strutil.SanitizeLabelName` | 只保留 `[a-zA-Z0-9_]`，其余替换为 `_`；`SanitizeFullLabelName` 额外保证不以数字开头（加 `_` 前缀），两函数语义不同 |
| `logging.Dedupe` 有后台协程 | 使用后必须 `Stop()`，否则 goroutine 泄漏（日志每 10s 做一次过期清理） |
