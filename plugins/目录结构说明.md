# Prometheus plugins 目录结构说明

> 基于 Prometheus v2.53 源码整理。
> `plugins/` 是 Prometheus 的**编译期「插件」注册包**：通过 Go 的空导入（`_ "..."`）触发
> 各服务发现（SD）子包的 `init()`，把它们的配置类型注册到 `discovery` 注册表中，
> 从而让 `prometheus.yml` 里的 `<name>_sd_configs` 能被正确解析。
> 注意：这里的「插件」是**编译期静态链接**，不是运行时动态加载（Go 原生不支持 `.so` 插件热插拔）。

## 一、机制说明（为什么需要这个目录）

服务发现实现分散在 `discovery/` 的 25 个子包里，但**配置文件解析器不能 import 它们**（会导致循环依赖、
也失去可裁剪性）。因此 Prometheus 采用「注册表 + 空导入」模式：

```
① 定义侧：discovery/registry.go
     RegisterConfig("kubernetes", ...)          → 注册配置键 kubernetes_sd_configs
           ▲
           │ init() 中调用
② 实现侧：discovery/kubernetes/、discovery/aws/…
           ▲
           │ 空导入触发 init()
③ 汇总侧：plugins/ 包（本目录）
     plugins.go    ← 由 plugins.yml 生成（23 个 SD）
     minimum.go    ← 手写（file、http 两个「最小集」SD）
           ▲
           │ main.go:69  _ "github.com/prometheus/prometheus/plugins"
④ 使用侧：cmd/prometheus/main.go → import 本包 → 全部 SD 被注册
           → config 解析 prometheus.yml 时认识所有 *_sd_configs
```

**如果缺少本包**：`prometheus.yml` 中写 `kubernetes_sd_configs` 会报
`field kubernetes_sd_configs not found in type config.plain` 之类的未知字段错误。

## 二、目录结构总览

```
plugins/
├── plugins.go     # ★ 生成文件：空导入 23 个 SD 包（由 plugins.yml 生成，勿手改）
├── minimum.go     # ★ 手写：空导入 file、http 两个基础 SD（构成最小可用集合）
└── generate.go    # 生成器：build tag `plugins`，读 ../plugins.yml 写出 plugins.go
```

> 目录无子目录，仅有 3 个 Go 文件，全部是「只有 import 副作用」或「代码生成」用途，
> 不含任何运行逻辑。

## 三、文件功能说明

| 文件 | 功能 |
|------|------|
| `plugins.go` | **生成文件**（文件头注明 `This file is generated by "make plugins"`）。以 `_ "github.com/prometheus/prometheus/discovery/xxx"` 形式空导入 23 个 SD 包：`aws`、`azure`、`consul`、`digitalocean`、`dns`、`eureka`、`gce`、`hetzner`、`ionos`、`kubernetes`、`linode`、`marathon`、`moby`、`nomad`、`openstack`、`ovhcloud`、`puppetdb`、`scaleway`、`triton`、`uyuni`、`vultr`、`xds`、`zookeeper`。**修改请改 `plugins.yml` 后重新生成，勿直接编辑** |
| `minimum.go` | **手写文件**，空导入 `discovery/file` 与 `discovery/http` 两个 SD。含义是：无论插件清单怎么裁剪，`file_sd_configs` 与 `http_sd_configs` 这两个「基础 SD」始终可用。它也解释了为什么 `plugins.yml` 里**不包含** file/http——它们由本文件固定提供 |
| `generate.go` | **代码生成器**。<br>• 受 `//go:build plugins` 约束，因此正常构建时被排除（且它是 `package main`，与同目录 `package plugins` 互斥，靠 build tag 隔离）<br>• 由 `//go:generate go run generate.go` 触发<br>• 逻辑：读取上级目录 `plugins.yml`（YAML 字符串列表）→ 拼接版权头 + `package plugins` + `import (...)` 块 → 覆盖写入 `plugins.go`<br>• 清单为空时只输出包头与 package 声明 |

## 四、归属

- **归属**：Prometheus **服务端二进制的编译期组件**（不是服务、无进程、无端口）。
  - 被 `cmd/prometheus/main.go` 以空导入方式引入（`main.go:69`）；
  - 影响的是**配置解析能力**：决定 `prometheus.yml` / `alertmanager_configs` 中允许出现哪些 `*_sd_configs`；
  - 与 `discovery/install/install.go` 的关系：`install` 包同样注册全部 SD（含 file/http），供库使用者一次性引入；
    `plugins` 包则是**由清单文件驱动的可裁剪版本**（`plugins.yml` + `minimum.go`），Prometheus 主程序用的是后者。
- 本包不包含任何业务逻辑，删除它会导致 SD 配置全部无法解析。

## 五、访问入口

### 1. 编译入口（生成与构建）

| 入口 | 说明 |
|------|------|
| `make plugins` | `Makefile:138` 定义，依赖 `plugins/plugins.go` |
| `plugins/plugins.go: plugins.yml plugins/generate.go` | `Makefile:134`，执行 `$(GO) generate -tags plugins ./plugins` |
| `go generate -tags plugins ./plugins` | 手工触发生成（等效于上面的 make 目标） |
| `make build` | `Makefile:142`：`build: assets npm_licenses assets-compress plugins common-build`，**正式构建前会先刷新插件清单** |

```bash
# 新增一个 SD 包后，在根目录 plugins.yml 里追加一行，然后：
make plugins                 # 重新生成 plugins/plugins.go
go build ./cmd/prometheus    # 重新编译，配置解析即认识新的 *_sd_configs
```

### 2. 代码入口

```go
// cmd/prometheus/main.go:69 —— 唯一引用点，靠副作用完成注册
import (
    _ "github.com/prometheus/prometheus/plugins" // Register plugins.
)
```

调用链：`main.go` 空导入 `plugins` → `plugins` 空导入各 `discovery/*` → 各包 `init()` 调用
`discovery.RegisterConfig(...)` → `config` 解析 YAML 时能识别对应键。

### 3. 配置入口（用户可见的效果）

被注册后，`prometheus.yml` 中可使用对应的配置键（`scrape_configs` 与 `alerting.alertmanagers` 均可）：

| SD 机制 | 配置键 | 来源 |
|---------|--------|------|
| Kubernetes | `kubernetes_sd_configs` | `plugins.go` |
| Consul | `consul_sd_configs` | `plugins.go` |
| DNS | `dns_sd_configs` | `plugins.go` |
| AWS EC2/Lightsail | `ec2_sd_configs` / `lightsail_sd_configs` | `plugins.go` |
| Azure | `azure_sd_configs` | `plugins.go` |
| GCE | `gce_sd_configs` | `plugins.go` |
| OpenStack | `openstack_sd_configs` | `plugins.go` |
| file | `file_sd_configs` | `minimum.go` |
| HTTP | `http_sd_configs` | `minimum.go` |
| 静态目标 | `static_configs` | `discovery/discovery.go`（内置，无需插件） |

（其余如 `digitalocean`/`hetzner`/`ionos`/`linode`/`marathon`/`moby`/`nomad`/`ovhcloud`/`puppetdb`/`scaleway`/`triton`/`uyuni`/`vultr`/`xds`/`zookeeper`/`eureka` 同理，键名为 `<name>_sd_configs`。）

### 4. 自定义/裁剪入口（库与下游项目）

| 需求 | 做法 |
|------|------|
| 去掉不需要的 SD（减小二进制） | 编辑根目录 `plugins.yml` 删除对应行 → `make plugins` → 重新编译 |
| 使用最小集合（仅 file/http） | 只导入 `github.com/prometheus/prometheus/plugins/minimum` 语义等价的包（`minimum.go` 同目录即同一包，需自行裁剪 `plugins.go` 或改用 `discovery/file`、`discovery/http` 直接空导入） |
| 一次性注册全部 SD（外部项目） | 空导入 `github.com/prometheus/prometheus/discovery/install` |
| 只注册某几个 SD | 空导入对应的 `discovery/<name>` 子包即可 |

## 六、注意事项

| 事项 | 说明 |
|------|------|
| 生成物勿手改 | `plugins.go` 会被 `make plugins` 覆盖；要增减 SD 请改 `plugins.yml` |
| 两个 package 共存靠 build tag | `generate.go` 是 `package main` + `//go:build plugins`，`plugins.go`/`minimum.go` 是 `package plugins`；不加 tag 会编译冲突 |
| `Makefile` 依赖关系 | `plugins/plugins.go` 依赖 `plugins.yml` 与 `generate.go` 的时间戳，二者更新后才会重新生成 |
| file/http 不在清单里 | 避免重复注册（`discovery/registry.go` 重复注册同名键会 panic），故由 `minimum.go` 单独固定引入 |
| 与 `discovery/install` 的区别 | `install` 面向库使用者（一次性全量）；`plugins` 面向 Prometheus 主程序（清单驱动、可裁剪） |
| 与「Go plugin」无关 | 不涉及 `.so` 动态加载，全部是编译期静态链接的 import 副作用 |
