# Prometheus promql 目录结构说明

> 基于 Prometheus v2.53 源码整理。
> `promql/` 是 Prometheus 的 **PromQL 查询引擎**（PromQL = Prometheus Query Language），
> 负责把 PromQL 字符串解析成 AST、编译成执行计划、在存储之上求值，最终产出
> `Vector` / `Matrix` / `Scalar` / `String` 结果。它是 Prometheus 的核心计算组件，
> 同时被 `promtool` 与外部项目（Thanos、Mimir 等）作为库使用。

## 一、整体架构（查询执行流程）

```
  用户 / Grafana / API 调用
        │  PromQL 字符串（如：rate(http_requests_total[5m]) > 0.5）
        ▼
  ┌──────────────────────────────────────────────────────────────┐
  │ 1. 解析：promql/parser                                        │
  │    lexer(lex.go) → generated_parser.y.go → AST(ast.go)        │
  │    parser.ParseExpr() 产出 Expr / EvalStmt                     │
  └───────────────────────────┬──────────────────────────────────┘
                              ▼
  ┌──────────────────────────────────────────────────────────────┐
  │ 2. 引擎：promql/engine.go                                     │
  │    NewEngine() → NewInstantQuery()/NewRangeQuery() → query    │
  │    执行计划：preprocessExpr → 按步骤/区间求值（execEvalStmt）    │
  │    并发控制、超时、样本上限、ActiveQueryTracker、查询日志        │
  └───────────────────────────┬──────────────────────────────────┘
                              ▼
  ┌──────────────────────────────────────────────────────────────┐
  │ 3. 求值算子                                                   │
  │    • 函数：functions.go（FunctionCalls 注册表，150+ 个函数）     │
  │    • 分位数：quantile.go（histogram_quantile 等）              │
  │    • 结果类型：value.go（Vector/Matrix/Scalar/String/Sample）   │
  └───────────────────────────┬──────────────────────────────────┘
                              ▼
  ┌──────────────────────────────────────────────────────────────┐
  │ 4. 数据源：storage.Queryable（fanoutStorage → tsdb / remote）  │
  └──────────────────────────────────────────────────────────────┘
                              ▼
              Result{Value, Warnings} → API JSON / 规则评估结果
```

## 二、目录结构总览

```
promql/
├── engine.go               # ★ 查询引擎核心：Engine、执行计划、求值循环、并发/超时控制
├── functions.go            # ★ PromQL 内置函数实现与 FunctionCalls 注册表
├── value.go                # ★ 查询结果类型：Vector / Matrix / Scalar / String / Sample
├── quantile.go             # 分位数计算：histogram_quantile、quantile、直方图桶处理
├── query_logger.go         # 活跃查询跟踪（ActiveQueryTracker）+ 查询日志
├── fuzz.go                 # 模糊测试入口（go-fuzz，构建标签限定）
├── bench_test.go           # 引擎基准测试（标准数据集压测）
├── engine_test.go / engine_internal_test.go   # 引擎单测与内部单测
├── functions_test.go       # 各函数单测
├── promql_test.go          # PromQL 端到端测试（含 histograms）
├── quantile_test.go        # 分位数计算单测
├── query_logger_test.go    # 活跃查询跟踪单测
├── value_test.go           # 结果类型单测
├── fuzz_test.go            # 模糊测试语料回归
│
├── parser/                 # ★ PromQL 语法解析器（独立子包，可单独使用）
├── promqltest/             # ★ PromQL 测试框架（.test 脚本、测试存储、LazyLoader）
└── fuzz-data/              # 模糊测试语料目录
```

## 三、顶层文件功能说明

| 文件 | 功能 |
|------|------|
| `engine.go` | **查询引擎核心**。<br>• `EngineOpts`：最大并发、超时、`MaxSamples`、`LookbackDelta`、`EnableAtModifier`/`EnableNegativeOffset`、`ActiveQueryTracker` 等选项<br>• `Engine` + `NewEngine()`：持有解析器、函数注册表与指标<br>• `Query` 接口：`Exec(ctx)` / `Statement()` / `Stats()` / `Cancel()` / `Close()`<br>• `NewInstantQuery()` / `NewRangeQuery()`：编译查询（解析 + 预处理 + 计划）<br>• `exec()` / `execEvalStmt()`：按 instant/range 求值，range 查询按 step 逐步执行<br>• 并发限流（`prometheus_engine_queries`、`queries_concurrent_max`）、超时中断、样本数上限、每步统计（per-step stats）<br>• `QueryEngine` 接口：便于替换/包装/mock |
| `functions.go` | **内置函数实现**。定义 `FunctionCall` 类型与 `FunctionCalls` 注册表（`"rate"`、`"histogram_quantile"`、`"label_replace"`、`"vector"` 等 150+ 个），每个函数形如 `func(vals []parser.Value, args parser.Expressions, enh *EvalNodeHelper) (Vector, annotations.Annotations)`；包含 range 向量函数（`funcRate`/`funcIrate`/`funcIncrease`…）、聚合辅助、字符串函数、直方图函数等 |
| `value.go` | **查询结果类型**：`Vector []Sample`、`Matrix []Series`、`Scalar`、`String`、`Sample`（含 `T`、`F` 浮点值、`H *FloatHistogram` 原生直方图、`Metric` 标签）、`Series`、`FPoint`；实现 `parser.Value` 接口（`Type()`/`String()`）及直方图辅助方法 |
| `quantile.go` | **分位数与直方图桶计算**：<br>• `bucketQuantile()`：经典直方图分位数（排序、合并同界桶、强制单调、二分定位桶后线性插值）<br>• `histogramQuantile()`：原生直方图分位数（支持反向迭代优化）<br>• `histogramFraction()`：区间占比计算<br>• `quantile()`：普通样本分位数<br>• `coalesceBuckets()` / `ensureMonotonicAndIgnoreSmallDeltas()`：数据清洗辅助 |
| `query_logger.go` | **活跃查询跟踪与查询日志**：`ActiveQueryTracker`（把正在执行的查询写入 `queries.active` mmap 文件，用于并发限制与故障排查）、`NewActiveQueryTracker()`、查询日志开关（`--query.log-file`）与慢查询记录 |
| `fuzz.go` | 模糊测试入口（`//go:build gofuzz`）：对 lexer/parser/AST 做模糊输入，发现解析器崩溃 |
| `bench_test.go` | 引擎基准测试：不同基数/选择器/函数的查询性能压测 |
| 其余 `*_test.go` | 与同名文件对应的单元测试；`promql_test.go` 为端到端用例（含 native histogram），`fuzz_test.go` 跑 `fuzz-data/` 语料回归 |

## 四、子目录功能说明

### 4.1 `parser/`——PromQL 语法解析器

| 文件 | 功能 |
|------|------|
| `lex.go` | 词法分析器（tokenizer）：把查询字符串切成标识符、数字、字符串、运算符、持续时间等 token，含关键字与指标名合法性校验 |
| `generated_parser.y` | goyacc 语法定义文件（PromQL 文法） |
| `generated_parser.y.go` | `make parser` 由 `.y` 生成的 LALR 解析器（**勿手改**） |
| `ast.go` | **AST 定义**：`Expr` 各种节点（`VectorSelector`、`MatrixSelector`、`Call`、`AggregateExpr`、`BinaryExpr`、`SubqueryExpr`、`StepInvariantExpr`、`ParenExpr`、`UnaryExpr`、`NumberLiteral`、`StringLiteral`），`EvalStmt`（求值语句：`Expr` + 时间范围 + 采样间隔）、`Expressions`、遍历/替换工具（`Walk`/`WalkVectors`/`Inspect`） |
| `parse.go` | **解析入口**：`ParseExpr()`（完整 PromQL → Expr）、`ParseMetric()`（指标名+标签）、`ParseMetricSelector()`（选择器 → matchers）、`ParseMetricSelectors()`、`ParseSeriesDesc()`（测试/回填用的序列描述语法）、`ParseDuration()`，以及语法校验与实验性函数开关 |
| `functions.go` | PromQL **函数签名表**（`Functions`）：函数名 → 参数个数/类型、返回类型、是否实验性；供解析阶段做参数类型检查 |
| `value.go` | `ValueType`（`vector`/`matrix`/`scalar`/`string`/`none`）、`Value`/`Sample`/`Series`/`FPoint` 等解析层值类型 |
| `printer.go` | AST → PromQL 字符串（`Expr.String()`），保证可往返解析 |
| `prettier.go` / `prettier_rules.md` | **表达式美化**：按规则重排缩进与换行（`Prettify()`），供 `format_query` API 使用；规则说明文档 |
| `posrange/` | 位置范围类型 `posrange.PositionRange`：AST 节点在原始查询字符串中的偏移，用于错误提示高亮 |
| `*_test.go` | 词法/语法/打印/美化测试 |

### 4.2 `promqltest/`——PromQL 测试框架

| 文件 | 功能 |
|------|------|
| `test.go` | **脚本化测试框架**：解析 `.test` 脚本（`load`/`eval`/`eval_fail`/`eval_warn`/`clear` 等指令），在内部测试存储上执行并比对结果；提供 `RunTest()`、`RunBuiltinTests()`、`NewTestEngine()`、`NewLazyLoader()`（惰性加载器，供 `promtool test rules` 复用）、`HistogramTestExpression()` 等 |
| `testdata/*.test` | 12 个内置测试脚本（`functions.test`、`aggregators.test`、`histograms.test` 等），随 `RunBuiltinTests` 自动执行 |
| `test_test.go` | 测试框架自身的测试 |

### 4.3 `fuzz-data/`
模糊测试语料（历史崩溃输入），由 `fuzz_test.go` 回归验证。

## 五、归属

- **归属服务**：Prometheus 服务端的**查询引擎**，随 `prometheus` 二进制运行；不是独立服务、无独立端口。
  - 服务端：处理所有 HTTP 查询 API、规则评估（记录规则/告警规则）、Web UI 图表查询；
  - 工具端：`promtool test rules` 用 `promql/promqltest` 在进程内验证规则与 PromQL 表达式；
- `promql` 与 `promql/parser` 也被 Thanos、Mimir、Cortex、Grafana 等外部项目作为库引用（`parser` 尤其常用于解析指标选择器）。

## 六、访问入口

### 1. 进程内代码入口（`cmd/prometheus/main.go:830`）

```go
opts := promql.EngineOpts{
    Logger:                   log.With(logger, "component", "query engine"),
    Reg:                      prometheus.DefaultRegisterer,
    MaxSamples:               cfg.queryMaxSamples,
    Timeout:                  time.Duration(cfg.queryTimeout),
    ActiveQueryTracker:       promql.NewActiveQueryTracker(localStoragePath, cfg.queryConcurrency, ...),
    LookbackDelta:            time.Duration(cfg.lookbackDelta),
    NoStepSubqueryIntervalFn: noStepSubqueryInterval.Get,
    EnableAtModifier:         true,
    EnableNegativeOffset:     true,
}
queryEngine = promql.NewEngine(opts)                          // main.go:845

// 规则管理器复用同一引擎做规则评估
QueryFunc: rules.EngineQueryFunc(queryEngine, fanoutStorage)  // main.go:850
```

调用方式：

```go
q, err := queryEngine.NewInstantQuery(ctx, fanoutStorage, queryOpts, "up", time.Now())
res := q.Exec(ctx)        // res.Value 为 promql.Vector/Matrix/Scalar/String

q, err = queryEngine.NewRangeQuery(ctx, fanoutStorage, queryOpts, expr, start, end, step)
```

### 2. HTTP 接口入口（`web/api/v1/api.go`）

| 接口 | 说明 | 底层 |
|------|------|------|
| `GET/POST /api/v1/query` | 瞬时查询 | `NewInstantQuery` → `Exec` |
| `GET/POST /api/v1/query_range` | 区间查询（按 step 求值） | `NewRangeQuery` → `Exec` |
| `GET/POST /api/v1/format_query` | 表达式美化 | `parser.ParseExpr` + `Prettify` |
| `GET/POST /api/v1/parse_query` | 解析为 AST JSON（调试用） | `parser.ParseExpr` |
| `GET/POST /api/v1/series`、`/api/v1/labels`、`/api/v1/label/<name>/values` | 元数据查询（不走引擎，直接用 storage） | `storage.Querier` |
| Web UI `/graph` | 图表页，浏览器直接调用上面的 query API | 同上 |

> Grafana、curl、`promtool query` 等客户端均通过上述 HTTP 接口使用引擎
> （`promtool query` 是 HTTP 客户端，不在进程内跑引擎；`promtool test rules` 才在进程内使用）。

### 3. 配置入口（启动 flag）

| flag | 作用 | 对应 `EngineOpts` |
|------|------|-------------------|
| `--query.max-concurrency` | 最大并发查询数 | `ActiveQueryTracker` 的并发上限 |
| `--query.timeout` | 单查询超时 | `Timeout` |
| `--query.max-samples` | 单查询最大加载样本数 | `MaxSamples` |
| `--query.lookback-delta` | 瞬时向量回看窗口 | `LookbackDelta` |
| `--enable-feature=promql-experimental-functions` | 开启实验性函数 | `parser.EnableExperimentalFunctions` |
| `--enable-feature=promql-per-step-stats` | 每步统计 | `EnablePerStepStats` |
| `--query.log-file` | 查询日志文件 | 查询日志器 |

### 4. 可观测入口

| 入口 | 内容 |
|------|------|
| `GET /metrics` | `prometheus_engine_queries`、`prometheus_engine_queries_concurrent_max`、`prometheus_engine_query_duration_seconds`（含 `slice` 分阶段耗时）、`prometheus_engine_query_samples_total`、`prometheus_engine_query_log_enabled`、每步统计相关指标 |
| 数据目录 `queries.active` | `ActiveQueryTracker` 写入的活跃查询 mmap 文件（`<storage.tsdb.path>/queries.active`），进程崩溃后可查看残留查询 |
| 查询日志文件 | `--query.log-file` 指定，记录超过阈值耗时的查询 |

## 七、关键实现要点

| 关注点 | 说明 | 相关文件 |
|--------|------|----------|
| 两阶段设计 | 解析（parser）与求值（engine）解耦，AST 可独立复用（Grafana/Thanos 只解析不求值） | `parser/`、`engine.go` |
| 执行计划 | 求值前先预编译：把 `@` 修饰符/负 offset 固定为 `StepInvariantExpr`、选择器下推 hints、分片 hints | `engine.go`（`preprocessExpr`） |
| 并发与限流 | 全局查询并发受 `--query.max-concurrency` 限制，超出排队；`ActiveQueryTracker` 落盘跟踪 | `engine.go`、`query_logger.go` |
| 区间查询实现 | 外层按 step 逐点求值，内层对 range 选择器按窗口滑动（避免重复计算） | `engine.go`、`functions.go` |
| 分位数算法 | 经典直方图线性插值 + 原生直方图精确计算，并对浮点精度误差做清洗 | `quantile.go` |
| 函数扩展点 | 新增函数只需实现 `FunctionCall` 并在 `FunctionCalls` 注册，同时在 `parser/functions.go` 声明签名 | `functions.go`、`parser/functions.go` |
| 测试方式 | `.test` 脚本（`load` → `eval` → 断言）驱动，内置测试在 `promqltest/testdata/` | `promqltest/` |
| 实验特性 | `EnableExperimentalFunctions`、`EnableAtModifier`、`EnableNegativeOffset`、`EnableDelayedNameRemoval` 等开关控制语义 | `engine.go`、`parser/` |
