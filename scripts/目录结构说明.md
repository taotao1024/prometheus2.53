# Prometheus scripts 目录结构说明

> 基于 Prometheus v2.53 源码整理。
> `scripts/` 是仓库的**工程化辅助脚本目录**：代码生成、前端资源打包、依赖升级、
> 发布、仓库间文件同步与 CI lint 配置模板。
> 它**不属于任何运行时服务**，不参与 `prometheus` 二进制的运行逻辑，
> 只在开发机（`make` 目标）与 GitHub Actions（CI/发布）中被调用。

## 一、定位说明

```
开发者本地 / GitHub Actions
        │
        ├─ make proto              → scripts/genproto.sh        → 生成 prompb/*.pb.go
        ├─ make assets-compress    → scripts/compress_assets.sh → 生成 web/ui/embed.go（内嵌 UI）
        ├─ make assets-tarball     → scripts/package_assets.sh  → 打包 UI tarball
        ├─ make update-npm-deps    → scripts/npm-deps.sh        → 升级前端依赖
        ├─ make ui-bump-version    → scripts/ui_release.sh      → 前端包版本/发布
        ├─ make check-go-mod-version → scripts/check-go-mod-version.sh → 多 go.mod 版本一致性
        └─ .github/workflows/repo_sync.yml → scripts/sync_repo_files.sh → 向其他仓库同步通用文件
                                          → scripts/golangci-lint.yml（被同步的 workflow 模板）
        tools.go（build tag: tools）→ 把 protobuf 生成工具钉进 go.mod
```

关键点：这些脚本**没有网络服务入口**，唯一「入口」是 **Makefile 目标**、**CI workflow** 或**直接执行脚本**；
所有脚本都假定从**仓库根目录**执行（`genproto.sh`、`sync_repo_files.sh` 会显式检查/切换工作目录）。

## 二、目录结构总览

```
scripts/
├── check-go-mod-version.sh   # 校验仓库内所有 go.mod 的 Go 版本一致
├── compress_assets.sh        # 压缩 web/ui 静态资源并生成 embed.go（二进制内嵌 UI）
├── package_assets.sh         # 将 web/ui 静态资源打包为 dist tarball
├── genproto.sh               # 生成 protobuf 绑定代码（prompb/、io/prometheus/client/）
├── npm-deps.sh               # 批量升级 web/ui 各 workspace 的 npm 依赖
├── ui_release.sh             # web/ui 多包发布工具（复制文件/校验版本/发包/清理）
├── sync_repo_files.sh        # 将通用文件同步到 prometheus 组织下其他仓库并开 PR
├── golangci-lint.yml         # 供同步到其他仓库的 golangci-lint workflow 模板
└── tools.go                  # 用 tools build tag 钉住代码生成工具依赖（不参与正式构建）
```

> 目录**无子目录**；本目录不含运行时代码，唯一 Go 文件 `tools.go` 受 `//go:build tools` 约束。

## 三、文件功能说明

| 文件 | 功能 | Makefile 目标 / 触发方 |
|------|------|------------------------|
| `check-go-mod-version.sh` | 用 `find` 找出仓库内所有 `go.mod`，提取各自的 `go` 指令版本，若**不止一种版本**则报错退出（返回 1）。保证主模块与 `documentation/examples`、`web/ui` 等子模块 Go 版本同步 | `make check-go-mod-version` |
| `compress_assets.sh` | 进入 `web/ui`，把 `embed.go.tmpl` 复制为 `embed.go`；对 `static/` 下所有文件执行 `gzip -k`（不带 `-k` 的 gzip 则用 `-f` 兜底）；最后把每个 `.gz` 文件写成 `//go:embed` 指令追加到 `embed.go`，并追加 `var EmbedFS embed.FS`。产物使 UI 静态文件**编译进二进制** | `make assets-compress`（依赖 `assets`） |
| `package_assets.sh` | 读取根目录 `VERSION`，把 `web/ui/static` 下的非 `.gz` 文件打包为 `.tarballs/prometheus-web-ui-<version>.tar.gz`，用于发布独立 UI 资源包（供 `--web.ui-*` 或外部托管使用） | `make assets-tarball` |
| `genproto.sh` | **protobuf 代码生成**：<br>1. 强制 `protoc` 版本为 **3.15.8**，否则退出 255<br>2. 备份 `go.sum`（`go install` 会改动它，结束时还原）<br>3. 安装 `goimports`、`protoc-gen-gogofast`、`protoc-gen-grpc-gateway`、`protoc-gen-swagger`<br>4. 对 `prompb/*.proto` 与 `prompb/io/prometheus/client/*.proto` 执行 `protoc --gogofast_out`<br>5. 用 `sed` 修正 import 路径（`golang/protobuf` → `gogo/protobuf`）并 `goimports` 格式化 | `make proto`（定义在 `Makefile.common:251`） |
| `npm-deps.sh` | 读取 `web/ui/package.json` 的 `workspaces`，对每个子包执行 `npx npm-check-updates -u --target <minor\|latest>`，最后 `npm install`。用于定期升级前端依赖 | `make update-npm-deps`（minor）<br>`make upgrade-npm-deps`（latest） |
| `ui_release.sh` | `web/ui` 多 workspace 发布工具，按参数执行：<br>• `--copy`：把 `LICENSE`、`CHANGELOG.md` 复制到各 workspace<br>• `--check-package <ver>`：校验各包版本是否等于目标版本<br>• `--bump-version <ver>`：同步 `@prometheus-io/*` 相互依赖版本并 `npm version --workspaces`<br>• `--publish [dry-run]`：逐个 workspace `npm publish --access public`（跳过私有包 `react-app`）<br>• `--clean`：删除前面复制进去的文件 | `make ui-bump-version` |
| `sync_repo_files.sh` | 把 `prometheus/prometheus` 中的通用文件（`CODE_OF_CONDUCT.md`、`LICENSE`、`Makefile.common`、`SECURITY.md`、`.yamllint`、`scripts/golangci-lint.yml`、部分 workflow 等）同步到 `prometheus` / `prometheus-community` 组织下所有仓库：拉取 → 复制 → 提交到 `repo_sync` 分支 → 推送 → 创建 PR。需要 `GITHUB_TOKEN`（脚本**禁止** `set -x` 以免泄漏 token） | GitHub Actions：`.github/workflows/repo_sync.yml` |
| `golangci-lint.yml` | **GitHub Actions workflow 模板**（不是 golangci-lint 的配置文件，本地配置是仓库根 `.golangci.yml`）：在 push/PR 时对 Go 代码跑 golangci-lint v1.59.0。该文件被 `sync_repo_files.sh` 同步到其他 Prometheus 仓库，因此注释里写明「This action is synced from ...」 | 由 `sync_repo_files.sh` 同步；本仓库实际 CI 见 `.github/workflows/ci.yml` |
| `tools.go` | `//go:build tools` + 空导入：把 `protoc-gen-gogofast`、`protoc-gen-grpc-gateway`、`protoc-gen-swagger`、`goimports` 记录为模块依赖，使其版本被 `go.mod`/`go.sum` 锁定（参照 golang/go#25922）。**不参与正常构建**，`go build ./...` 时被 build tag 排除 | 无（仅依赖声明） |

## 四、归属

- **归属**：Prometheus 仓库的**构建/发布/维护工具集**，属于「工程化基础设施」而非运行时组件。
  - 与运行时无关：不会被编译进 `prometheus`、`promtool` 二进制（`tools.go` 也被 build tag 排除）；
  - 与 CI/CD 相关：由 `Makefile`（本地）与 `.github/workflows/`（CI/发布）调用；
  - 部分脚本面向**跨仓库治理**：`sync_repo_files.sh` + `golangci-lint.yml` 用于向 `prometheus` / `prometheus-community` 下其他项目传播统一规范。

## 五、访问入口（调用方式）

### 1. Makefile 目标（本地主要入口）

| make 目标 | 调用脚本 | 作用 |
|-----------|----------|------|
| `make proto` | `genproto.sh` | 重新生成 protobuf 代码 |
| `make assets-compress` | `compress_assets.sh` | 生成 gzip 资源 + `web/ui/embed.go` |
| `make assets-tarball` | `package_assets.sh` | 打包 UI 资源 tarball |
| `make update-npm-deps` | `npm-deps.sh "minor"` | 升级前端依赖（minor） |
| `make upgrade-npm-deps` | `npm-deps.sh "latest"` | 升级前端依赖（latest） |
| `make ui-bump-version` | `ui_release.sh --bump-version` | 批量改前端包版本 |
| `make check-go-mod-version` | `check-go-mod-version.sh` | 校验多 `go.mod` Go 版本一致 |

> `make assets` = `ui-install` + `ui-build`（`cd web/ui && npm run build`），是 `assets-compress`/`assets-tarball` 的前置。

### 2. 直接执行（须在仓库根目录）

```bash
./scripts/check-go-mod-version.sh
./scripts/genproto.sh                 # 需要 protoc 3.15.8 在 PATH
./scripts/compress_assets.sh          # 需要已构建 web/ui/static
./scripts/package_assets.sh
./scripts/ui_release.sh --check-package 2.53.0
GITHUB_TOKEN=xxx ./scripts/sync_repo_files.sh
```

### 3. CI / 自动化入口

| 入口 | 说明 |
|------|------|
| `.github/workflows/repo_sync.yml` | 定时/手动触发 `./scripts/sync_repo_files.sh`（注入 `PROMBOT_GITHUB_TOKEN`） |
| `.github/workflows/ci.yml` | 主 CI：lint（golangci-lint v2.1.5，注释要求与 `Makefile.common`、`scripts/golangci-lint.yml` 保持同步）、测试、构建 |
| `.github/workflows/fuzzing.yml` | 模糊测试（对应 `promql/fuzz.go`、`fuzz-data/`） |
| 其他仓库 | 通过 `sync_repo_files.sh` 获得 `scripts/golangci-lint.yml` 后，在其仓库中作为 workflow 运行 |

### 4. 产物入口（脚本生成物被谁消费）

| 产物 | 消费方 |
|------|--------|
| `web/ui/embed.go`（`//go:embed` + `EmbedFS`） | `web/ui` 包 → `web/web.go` 提供 UI 静态文件，编译进二进制 |
| `prompb/*.pb.go`、`prompb/io/prometheus/client/metrics.pb.go` | `storage/remote/`（远程读写协议）、`util/fmtutil` |
| `.tarballs/prometheus-web-ui-<version>.tar.gz` | 发布产物（独立 UI 资源包） |
| `web/ui/*/package.json` 版本变更 | npm registry（`@prometheus-io/*` 包） |

## 六、注意事项

| 事项 | 说明 |
|------|------|
| 工作目录 | 所有脚本假定在**仓库根目录**执行；`genproto.sh` 会校验自身路径，`sync_repo_files.sh` 会 `cd $(git rev-parse --show-cdup)` |
| protoc 版本硬校验 | `genproto.sh` 要求 `protoc 3.15.8`，版本不符直接退出，避免生成代码差异 |
| go.sum 被临时修改 | `genproto.sh` 会备份 `go.sum` 并在结束（含失败）后还原 |
| 不要手改生成物 | `*.pb.go`、`web/ui/embed.go` 均为生成文件，改动会在下次运行时被覆盖；对应源文件是 `*.proto`、`web/ui/embed.go.tmpl` |
| token 安全 | `sync_repo_files.sh` 明确禁止 `set -x`（避免泄漏 `GITHUB_TOKEN`）；该 token 需要 `repo`/`public_repo` 权限 |
| 依赖外部命令 | bash、`find`/`sed`/`gzip`/`tar`/`jq`、`npm`/`npx`、`protoc`、`go`（详见各脚本） |
| Windows 环境 | 脚本均为 bash 脚本，Windows 需在 WSL / Git Bash 下运行（`sed -i` 在 macOS 与 Linux 的语法差异已由 `ui_release.sh` 分别处理） |
