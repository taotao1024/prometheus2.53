# Prometheus rules 目录结构说明

> 基于 Prometheus v2.53 源码整理。
> `rules/` 是 Prometheus 的**规则评估引擎**：周期性地执行 `rule_files` 中定义的
> **记录规则（recording rule）** 与 **告警规则（alerting rule）**，
> 记录规则把查询结果写回存储，告警规则产生告警并推送给 Alertmanager。
> 它随 `prometheus` 二进制运行（**Server 模式**；Agent 模式不加载规则），不是独立服务。

## 一、整体架构（规则评估流程）

```
 prometheus.yml: rule_files: [rules/*.yml]
        │
        ▼
 ① 加载：rulefmt 解析规则文件 → Manager.LoadGroups() / Update()
        │  每个 group = 一组规则 + interval + limit + labels/annotations
        ▼
 ② 调度：Manager.Run() → start() → 每个 Group 启动独立 goroutine（Group.run）
        │  按 group.interval 对齐执行（EvalTimestamp 用 hash 做错峰，避免同时触发）
        ▼
 ③ 评估：Group.Eval(ts)
        │  并发评估组内所有规则（每条规则一个 goroutine）
        ├── RecordingRule.Eval() → QueryFunc(PromQL) → Appendable(Appender) 写回 TSDB
        │      产出指标系列（带 external labels + rule labels）
        └── AlertingRule.Eval() → QueryFunc(PromQL) → 维护 active alerts 状态机
               ├ 指标：ALERTS / ALERTS_FOR_STATE
               └ NotifyFunc(告警批次) → notifier → POST /api/v1/alerts 到 Alertmanager
        ▼
 ④ 观测：prometheus_rule_* 指标、/api/v1/rules、/api/v1/alerts、Web UI /rules 页面
```

## 二、目录结构总览

```
rules/
├── manager.go            # ★ 规则管理器：加载/热更新规则文件、管理所有 Group、对外查询接口
├── group.go              # ★ 规则组：定时调度、并发评估组内规则、组级指标、状态恢复
├── rule.go               # ★ Rule 接口与健康状态定义（记录规则/告警规则的公共契约）
├── alerting.go           # ★ 告警规则实现（Alert 状态机、for/keep_firing_for、ALERTS 指标）
├── recording.go          # ★ 记录规则实现（求值结果写回存储）
├── origin.go             # 规则来源上下文（RuleDetail/OriginContext，注入查询 ctx 用于追踪）
├── manager_test.go       # 管理器测试（加载、热更新、指标、并发）
├── group_test.go         # 规则组调度与评估测试
├── alerting_test.go      # 告警规则测试（状态转换、恢复、keep_firing_for）
├── recording_test.go     # 记录规则测试
├── origin_test.go        # 来源上下文测试
└── fixtures/             # 测试用规则文件（YAML）
    ├── rules.yaml
    ├── rules2.yaml
    ├── rules2_copy.yaml
    ├── rules_multiple.yaml
    ├── rules_multiple_groups.yaml
    ├── rules_multiple_independent.yaml
    └── rules_dependencies.yaml
```

## 三、文件功能说明

| 文件 | 功能 |
|------|------|
| `manager.go` | **规则管理器核心**。<br>• `ManagerOptions`：`QueryFunc`（PromQL 执行）、`NotifyFunc`（告警发送）、`Appendable`（记录规则写入）、`Queryable`、`ExternalURL`、`Registerer`、`OutageTolerance`/`ForGracePeriod`/`ResendDelay` 等<br>• `NewManager()` / `Run()` / `Stop()`：生命周期管理<br>• `Update()`：**热更新入口**（配置重载时对比文件内容，仅重启变化的 group）<br>• `LoadGroups()`：解析 `rule_files` 并构造 `Group`<br>• `GroupLoader` 接口：抽象规则文件加载（便于测试替换）<br>• `RuleGroups()` / `Rules()` / `AlertingRules()`：供 API 查询当前规则<br>• `EngineQueryFunc()`：把 `promql.Engine` 包装成 `QueryFunc`<br>• `DefaultEvalIterationFunc` / `GroupEvalIterationFunc`：组评估迭代逻辑扩展点 |
| `group.go` | **规则组**。<br>• `Group`：一组规则的集合，含 `interval`、`limit`、`evalIterationFunc`、组级指标、`terminated` 通道<br>• `NewGroup()` / `run()` / `Eval()`：按 interval 对齐调度、并发评估组内规则、合并错误与 warnings<br>• `EvalTimestamp()`：用组名 hash 对 interval 取模做**错峰**，避免所有组在同一秒齐发<br>• `RestoreForState()`：从 `ALERTS_FOR_STATE` 恢复告警状态（重启后保持 for 计时）<br>• `GroupMetrics`：`prometheus_rule_group_interval_seconds`、`prometheus_rule_group_last_duration_seconds`、`prometheus_rule_group_last_evaluation_timestamp_seconds`、`prometheus_rule_group_rules` 等 |
| `rule.go` | **规则公共契约**：`RuleHealth`（`ok`/`err`/`unknown`）、`Rule` 接口（`Name()`/`Labels()`/`Query()`/`Eval()`/`Health()`/`LastError()`/`SetHealth()`/`SetLastError()`），以及 `RuleDetail`（规则名、文件、组等元信息的轻量描述） |
| `alerting.go` | **告警规则**：<br>• `AlertState` 枚举：`StateInactive` → `StatePending` → `StateFiring`<br>• `Alert`：单条告警实例（Labels/Annotations/State/ActiveAt/FiredAt/ResolvedAt/Value）<br>• `AlertingRule`：`NewAlertingRule()`、`Eval()`（维护 active map、处理 `for`/`keep_firing_for`/`resolvedRetention`、生成 `ALERTS`/`ALERTS_FOR_STATE` 指标）<br>• `State()` / `ActiveAlerts()` / `ActiveAlertsCount()`：供 API 展示<br>• `SendAlerts()`：把告警批次发给 `notifier.Manager`（`Alertmanager` 出口） |
| `recording.go` | **记录规则**：`RecordingRule`、`NewRecordingRule()`。`Eval()` 执行 PromQL 并把结果加上 rule labels 后通过 `Appender` 写回存储（生成新指标系列）；同时更新 `prometheus_rule_evaluations_total` / `prometheus_rule_evaluation_failures_total` 等指标 |
| `origin.go` | **规则来源上下文**：`RuleDetail`、`NewRuleDetail()`、`NewOriginContext()`。把「当前查询由哪条规则、哪个文件触发」注入 `context`，供查询追踪（`--enable-feature=...` 追踪/日志）与远程查询传递使用 |
| `*_test.go` | 各组件单元测试：规则加载与热更新、组调度错峰、告警状态机（pending→firing→inactive）、规则依赖排序、指标正确性 |
| `fixtures/*.yaml` | 测试用规则文件：单组/多组/多文件、规则间依赖（`rules_dependencies.yaml`）、内容相同用于热更新比对的副本（`rules2_copy.yaml`）等 |

## 四、归属

- **归属服务**：Prometheus **Server 模式**的规则评估组件，随 `prometheus` 二进制运行；**不是独立服务、无独立端口**。
  - 上游依赖：`promql`（执行表达式）、`storage`（`Appendable` 写回记录规则结果、`Queryable` 读取）、`notifier`（发送告警）、`rulefmt`（规则文件解析）；
  - Agent 模式**不启动**规则管理器（Agent 只做抓取+远程写）；
- 同样的代码也被 **promtool**（`promtool check rules`、`promtool test rules`）复用做规则校验与单元测试。

## 五、访问入口

### 1. 配置入口（`prometheus.yml`）

```yaml
global:
  evaluation_interval: 1m        # 规则组默认评估间隔（group 未指定 interval 时使用）

rule_files:
  - "rules/*.yml"                # 规则文件（glob，支持多个/多层目录）
  - "alerts/*.yml"

alerting:                        # 告警规则的出口：Alertmanager
  alertmanagers:
    - static_configs:
        - targets: ["127.0.0.1:9093"]

# 规则组示例（rules/*.yml 内）
groups:
  - name: example
    interval: 30s                # 覆盖全局 evaluation_interval
    limit: 100                   # 单条规则最大返回样本数
    rules:
      - record: job:http_requests:rate5m      # 记录规则
        expr: sum by (job) (rate(http_requests_total[5m]))
      - alert: HighErrorRate                  # 告警规则
        expr: job:http_errors:ratio5m > 0.05
        for: 5m                               # pending → firing 的门槛时长
        keep_firing_for: 5m                   # 条件消失后保持 firing 的时长
        labels: { severity: page }
        annotations: { summary: "错误率过高" }
```

启动 flag（对应 `ManagerOptions` 字段）：

| flag | 说明 |
|------|------|
| `--rules.alert.resend-delay` | 同一告警重复发送的最小间隔（`ResendDelay`） |
| `--rules.alert.for-outage-tolerance` | 重启恢复时允许的 for 状态缺口（`OutageTolerance`） |
| `--rules.alert.for-grace-period` | 恢复时对 for 计时的宽限期（`ForGracePeriod`） |
| `--rules.max-concurrent-evals` | 规则并发评估上限 |
| `--storage.tsdb.path` 下的 `alerts` | 告警状态持久化文件（`<path>/alerts`），重启后恢复 pending/firing 状态 |

### 2. 进程内代码入口（`cmd/prometheus/main.go:847`）

```go
ruleManager = rules.NewManager(&rules.ManagerOptions{
    Appendable:  fanoutStorage,                                    // 记录规则结果写回
    Queryable:   localStorage,
    QueryFunc:   rules.EngineQueryFunc(queryEngine, fanoutStorage), // PromQL 执行
    NotifyFunc:  rules.SendAlerts(notifierManager, externalURL),    // 告警出口
    Context:     ctxRule,
    ExternalURL: cfg.web.ExternalURL,
    Registerer:  prometheus.DefaultRegisterer,
    Logger:      log.With(logger, "component", "rule manager"),
})

// 启动/停止（run.Group 中的 actor）
ruleManager.Run()   // main.go:1124
ruleManager.Stop()  // main.go:1128

// 配置热重载时（reloader "rules"）
ruleManager.Update(interval, files, externalLabels, externalURL, groupEvalIterationFunc)
```

### 3. HTTP 接口入口（`web/api/v1/api.go`）

| 接口 | 说明 | 数据来源 |
|------|------|----------|
| `GET /api/v1/rules` | 所有规则组及规则列表（type/health/lastError/evaluationTime/duration/alerts） | `Manager.RuleGroups()` |
| `GET /api/v1/alerts` | 当前所有活跃告警 | `Manager.AlertingRules()` → `ActiveAlerts()` |
| `GET /graph`、`/alerts`、`/rules` | Web UI 页面：Alerts / Rules 列表 | 浏览器调用上述 API |
| `GET /api/v1/status/runtimeinfo` | 运行状态（含规则评估相关信息） | 运行时 |

> 出口方向：告警通过 `notifier` 发送到 Alertmanager 的 `POST /api/v1/alerts`
> （协议定义见 `notifier/`，非本目录）。

### 4. CLI 入口（promtool）


| 入口 | 内容 |
|------|------|
| `GET /metrics` | `prometheus_rule_evaluations_total`、`prometheus_rule_evaluation_failures_total`、`prometheus_rule_group_interval_seconds`、`prometheus_rule_group_last_duration_seconds`、`prometheus_rule_group_last_evaluation_timestamp_seconds`、`prometheus_rule_group_rules`、`prometheus_rule_group_iterations_total` |

## 六、关键实现要点

| 关注点 | 说明 | 相关代码 |
|--------|------|----------|
| 热更新最小化重启 | `Update()` 按文件名比对：内容未变的 group 保持运行，变化的才停止重建 | `manager.go` |
| 评估错峰 | `EvalTimestamp()` 用组名 hash % interval 计算偏移，避免所有组同一时刻齐发 | `group.go` |
| 并发评估 | 组内每条规则一个 goroutine，受 `--rules.max-concurrent-evals` 限制 | `group.go` |
| `limit` 保护 | group/rule 的 `limit` 限制单次查询返回样本数，防止规则拖垮实例 | `group.go`、`rule.go` |
| 告警状态机 | pending（`for` 未满）→ firing（`for` 满足）→ inactive；`keep_firing_for` 延长保持 | `alerting.go` |
| 重启状态恢复 | 从 `ALERTS_FOR_STATE` 重建 active alerts，结合 `--rules.alert.for-outage-tolerance`/`for-grace-period` | `group.go` `RestoreForState()` |
| 规则依赖顺序 | 同组内若规则引用了其他记录规则的输出，按依赖排序评估（`rules_dependencies.yaml` 测试覆盖） | `group.go` |
| 来源追踪 | 评估时把 `RuleDetail` 注入 context，可追踪到具体规则/文件 | `origin.go` |
