# Prometheus web 目录结构说明

> 基于 Prometheus v2.53 源码整理。
> `web/` 是 Prometheus 的 **HTTP 服务层**——整个 Prometheus 中**唯一监听网络端口**的组件
> （默认 `:9090`）。它提供：React Web UI、`/api/v1/*` HTTP API、`/federate` 联邦、
> 自监控 `/metrics`、健康检查与生命周期管理端点（`/-/reload` 等）。
> 它是 `prometheus` 二进制的一部分（不是独立服务），Server 与 Agent 模式共用
> （Agent 下查询/规则类接口通过 `wrapAgent` 返回 422 禁用）。

## 一、整体架构（请求流）

```
main.go
   │  web.New(logger, &web.Options{...})          （注入 storage/engine/rules/scrape/notifier）
   ▼
Handler.Run(ctx, listener, webConfig)
   │  route.Router（root router + /api/v1 router）
   ├── 中间件：requestCounter/Duration/ResponseSize 指标、TLS（exporter-toolkit，--web.config.file）
   ├── UI：React 应用（编译产物内嵌，`web/ui` → `scripts/compress_assets.sh` → embed.FS）
   │        /graph /targets /service-discovery /alerts /rules /status /tsdb-status /config ...
   ├── API：/api/v1/*（api/v1/api.go，约 40 个端点）
   │        查询、标签、series、targets/alerts/rules、status、远程读写、OTLP、TSDB 管理
   ├── 数据出口：/federate（联邦导出）、/metrics（自监控）
   ├── 生命周期：/-/healthy /-/ready /-/reload /-/quit /debug/pprof
   ▼
处理时通过 h.options 引用其它组件：
   storage / exemplarStorage（查询）、queryEngine（PromQL）、
   scrapeManager / ruleManager / notifier（targets、alerts、rules 展示）、
   reloadCh / quitCh（与 main 的 run.Group 联动）
```

## 二、目录结构总览

```
web/
├── web.go             # ★ HTTP 服务主入口：Handler、Options、路由注册、中间件、生命周期端点
├── federate.go        # ★ 联邦导出 /federate 的实现
├── web_test.go        # Handler/路由/ready/参数解析测试
├── federate_test.go   # 联邦导出测试
├── api/
│   └── v1/            # ★ HTTP API v1 实现
│       ├── api.go         # 全部 API 端点注册与处理函数
│       ├── codec.go       # 响应编码协商（默认 JSON / protobuf）
│       ├── json_codec.go  # 基于 util/jsonutil 的 JSON 编码实现
│       └── *_test.go      # codec 与 API 测试
└── ui/                # ★ React 前端（npm workspace）
    ├── ui.go              # Go 侧静态资源入口（Assets http.FileSystem，build tag !builtinassets）
    ├── assets_embed.go    # build tag builtinassets：内嵌版 Assets（来自 embed.FS）
    ├── embed.go.tmpl      # 模板：compress_assets.sh 生成 embed.go（//go:embed *.gz）
    ├── build_ui.sh        # UI 构建脚本
    ├── package.json       # npm workspaces 根（react-app / module/*）
    ├── react-app/         # React 应用源码（pages/components/hooks/themes...）
    ├── module/            # 可发布的前端库：codemirror-promql、lezer-promql（PromQL 编辑器/语法）
    └── static/            # 构建产物（由 make assets 生成，embed 进二进制）
```

## 三、文件功能说明

### 3.1 `web.go`（HTTP 服务主入口）

| 元素 | 作用 |
|------|------|
| `Options` | 装配参数：`Context`、`TSDBRetentionDuration`/`TSDBDir`/`TSDBMaxBytes`、`LocalStorage`、`Storage`、`ExemplarStorage`、`QueryEngine`、`ScrapeManager`、`RuleManager`、`Notifier`、`Gatherer`、`Registerer`、`LookbackDelta`、`RoutePrefix`/`ExternalURL`、`ReadTimeout`/`MaxConnections`、`EnableLifecycle`、`EnableRemoteWriteReceiver`、`AgentMode`、`UserAssetsPath`、`CORSOrigin` 等 |
| `Handler` | 持有 router、apiV1、各组件引用、ready 状态、reload/quit 通道、启动时间、flags 等 |
| `New(logger, o)` | 构建 Handler 并注册全部路由 |
| `Run(ctx, listener, webConfig)` | 启动 HTTP 服务：支持 `--web.config.file` 的 TLS/BasicAuth（exporter-toolkit）；优雅退出 |
| `Listener()` | 允许在 `Run` 前预占端口（测试/自检用） |
| `SetReady(v)` / `isReady()` / `testReady()` | **就绪门控**：TSDB/WAL 未就绪时数据类接口返回 503 |
| `Reload()` / `reload()` | `/-/reload` 的实现：向 main 的 reloader 链发送重载请求并回传结果 |
| `Quit()` / `quit()` | `/-/quit` 的实现：优雅关闭进程（需 `--web.enable-lifecycle`） |
| `version()` / `runtimeInfo()` / `consoles()` | `/version`、runtimeinfo 数据源、consoles 模板目录服务 |
| `setPathWithPrefix()` | 支持 `--web.route-prefix` 把所有路由挂到子路径 |

**路由注册表（root 级）**：

| 路由 | 说明 |
|------|------|
| `/`、`/graph`、`/targets`、`/service-discovery`、`/alerts`、`/rules`、`/status`、`/tsdb-status`、`/config` | React UI 页面（serveReactApp，SPA 路由） |
| `/static/*filepath`、`/classic/static/*filepath` | UI 静态资源（内嵌 embed.FS） |
| `/user/*filepath` | 用户自定义静态文件（`--web.user-assets`） |
| `/consoles/*filepath` | 控制台模板（`--web.console.templates`，需就绪） |
| `/metrics` | **Prometheus 自身指标**（自监控抓取的目标） |
| `/federate` | 联邦导出（`federate.go`） |
| `/version` | 构建版本信息 |
| `/-/healthy` | 存活检查（始终 200） |
| `/-/ready` | 就绪检查（TSDB/WAL 未就绪时 503） |
| `POST|PUT /-/reload` | 热重载配置（`--web.enable-lifecycle`，否则 GET 返回提示、POST 返回 403） |
| `POST|PUT /-/quit` | 优雅退出（`--web.enable-lifecycle`） |
| `/debug/*subpath` | pprof 调试端点 |
| `/-/quit`、`/-/reload`（GET） | 返回提示信息 |

### 3.2 `federate.go`（联邦导出）

| 元素 | 作用 |
|------|------|
| `federation(w, req)` | `GET /federate?match[]=<selector>` 的实现：按 match[] 查询各 series 的**最新样本**，以 Prometheus 文本格式输出（时间戳为抓取时间）；用于分层 Prometheus 架构（下级 → 上级抓取） |
| `registerFederationMetrics` | 注册联邦相关计数指标 |

### 3.3 `api/v1/`（HTTP API v1）

| 文件 | 作用 |
|------|------|
| `api.go` | **全部 API 端点**（见下表）+ 通用包装：`wrap`（错误→JSON）、`wrapAgent`（Agent 模式禁用返回 422）、`ready`（就绪门控） |
| `codec.go` | 响应格式协商：`Accept` 头选 JSON 或 protobuf；错误类型定义（`errorType` → HTTP 状态码映射） |
| `json_codec.go` | 默认 JSON 编码，基于 `util/jsonutil` 的流式 jsoniter（高性能序列化 Vector/Matrix/Histogram） |

**API 端点表（均挂在 `/api/v1` 前缀下）**：

| 分组 | 端点 | 说明 | Agent 模式 |
|------|------|------|------------|
| 查询 | `GET/POST /query` | 即时查询（PromQL，支持 `stats`、`query` 参数） | 禁用 |
| 查询 | `GET/POST /query_range` | 区间查询 | 禁用 |
| 查询 | `GET/POST /query_exemplars` | exemplar 查询 | 禁用 |
| 查询 | `GET/POST /format_query` | PromQL 格式化 | 可用 |
| 标签 | `GET/POST /labels` | 标签名列表（可带 match[]/start/end） | 禁用 |
| 标签 | `GET /label/:name/values` | 标签值列表 | 禁用 |
| 序列 | `GET/POST /series` | 序列匹配查询 | 禁用 |
| 序列 | `DELETE /series` | 丢弃序列（`--enable-feature=experimental` + admin api） | 禁用 |
| 观测 | `GET /scrape_pools` | 抓取池列表 | 404 |
| 观测 | `GET /targets` | 抓取目标（active/dropped） | 404 |
| 观测 | `GET /targets/metadata` | 目标级元数据 | 404 |
| 观测 | `GET /metadata` | 全量指标元数据 | 404 |
| 告警规则 | `GET /alerts` | 活跃告警 | 禁用 |
| 告警规则 | `GET /rules` | 规则组与规则 | 禁用 |
| 告警规则 | `GET /alertmanagers` | Alertmanager 发现状态 | 禁用 |
| 状态 | `GET /status/config` | 当前配置（脱敏） | 可用 |
| 状态 | `GET /status/runtimeinfo` | 运行时信息（CWD、GOMAXPROCS 等） | 可用 |
| 状态 | `GET /status/buildinfo` | 版本信息 | 可用 |
| 状态 | `GET /status/flags` | 启动 flag | 可用 |
| 状态 | `GET /status/tsdb` | TSDB 状态（head stats、cardinality top-N） | 禁用 |
| 状态 | `GET /status/walreplay` | WAL 回放进度 | 可用 |
| 远程 | `POST /read` | **remote read** 接收端 | 禁用 |
| 远程 | `POST /write` | **remote write** 接收端（`--enable-feature=remote-write-receiver`） | 禁用 |
| 远程 | `POST /otlp/v1/metrics` | **OTLP 写入**接收端（`--enable-feature=otlp-write-receiver`） | 禁用 |
| 管理 | `POST|PUT /admin/tsdb/snapshot` | 快照（`--web.enable-admin-api`） | 禁用 |
| 管理 | `POST|PUT /admin/tsdb/delete_series` | 逻辑删除（`--web.enable-admin-api`） | 禁用 |
| 管理 | `POST|PUT /admin/tsdb/clean_tombstones` | 清理墓碑（`--web.enable-admin-api`） | 禁用 |

### 3.4 `ui/`（React 前端）

| 文件/目录 | 作用 |
|-----------|------|
| `ui.go` | `build tag !builtinassets`：开发态从磁盘读取 `web/ui/static`；`Assets` 变量为 `http.FileSystem` |
| `assets_embed.go` | `build tag builtinassets`：正式构建使用 `embed.FS` 内嵌资源（由 `scripts/compress_assets.sh` 生成的 `embed.go` 提供 `//go:embed *.gz`） |
| `embed.go.tmpl` | `embed.go` 的模板 |
| `build_ui.sh` | UI 构建脚本 |
| `package.json` | npm workspaces 根：`react-app`、`module/*` |
| `react-app/` | React UI 源码（pages/components/hooks/themes/utils，Graph/Table 页面等） |
| `module/codemirror-promql` | CodeMirror 6 的 PromQL 语法高亮/补全插件（发布为 npm 包 `@prometheus-io/codemirror-promql`） |
| `module/lezer-promql` | PromQL 的 Lezer 语法树定义（`@prometheus-io/lezer-promql`） |
| `static/` | `make assets` 的构建产物（`scripts/compress_assets.sh` 会 gzip 并生成 embed 指令） |

> 前端开发中改 UI 需 `make assets` 重新构建；改后端只需编译 Go。

## 四、归属

- **归属**：`prometheus` 二进制的 **HTTP 服务层**（Server 与 Agent 共用）。
  - **依赖注入方向**：`main.go` 把 storage、queryEngine、scrapeManager、ruleManager、notifier 等以 `web.Options` 传入 `web.New()`——web 是各组件的**展示聚合层**，不含业务逻辑；
  - **生命周期联动**：`/-/reload` → `Handler.Reload()` → main 的 reloader 链（scrape_sd、notify_sd、rules、web、tracing 等）；`/-/quit` → 优雅退出；
  - 就绪状态由 main 在 WAL 回放/TSDB 就绪后调用 `SetReady(true)` 控制。
- 该包同样被外部项目作为库引用（如 Thanos 的 Query 前端借鉴其 UI 结构）。

## 五、访问入口

### 1. 启动配置（对应 `web.Options`）

| flag | 作用 |
|------|------|
| `--web.listen-address` | 监听地址，默认 `0.0.0.0:9090` |
| `--web.config.file` | TLS / BasicAuth / header 配置（exporter-toolkit） |
| `--web.route-prefix` / `--web.external-url` | 子路径部署 / 生成回链 URL |
| `--web.enable-lifecycle` | 启用 `/-/reload`、`/-/quit` |
| `--web.enable-admin-api` | 启用 `/admin/tsdb/*` |
| `--web.max-connections` | 最大并发连接数 |
| `--web.read-timeout` | 读超时 |
| `--web.user-assets` | `/user/` 静态文件目录 |
| `--web.console.templates` / `--web.console.libraries` | consoles 模板 |
| `--enable-feature=remote-write-receiver,otlp-write-receiver` | 启用写入接收端 |

### 2. HTTP 入口（用户侧主要交互点）

| 类别 | 入口 |
|------|------|
| Web UI | `/`（首页/graph）、`/targets`、`/service-discovery`、`/alerts`、`/rules`、`/status`、`/tsdb-status`、`/config` |
| 查询 API | `GET|POST /api/v1/query`、`/api/v1/query_range`、`/api/v1/query_exemplars`、`/api/v1/format_query` |
| 元数据 API | `/api/v1/labels`、`/api/v1/label/{name}/values`、`/api/v1/series`、`/api/v1/metadata` |
| 观测 API | `/api/v1/targets`、`/api/v1/scrape_pools`、`/api/v1/targets/metadata`、`/api/v1/alerts`、`/api/v1/rules`、`/api/v1/alertmanagers` |
| 状态 API | `/api/v1/status/{config,runtimeinfo,buildinfo,flags,tsdb,walreplay}` |
| 数据交换 | `POST /api/v1/read`（remote read）、`POST /api/v1/write`（remote write receiver）、`POST /api/v1/otlp/v1/metrics` |

| 联邦 | `GET /federate?match[]={job="node"}` |

| 存活/就绪 | `GET /-/healthy`、`GET /-/ready` |

| 版本 | `GET /version` |

**联邦用法示例**（上级 Prometheus 抓取下级）：

```yaml
scrape_configs:
  - job_name: federate
    honor_labels: true
    metrics_path: /federate
    params:
      match[]:
        - '{job=~".+"}'
    static_configs:
      - targets: ['sub-prometheus:9090']
```

### 3. 进程内代码入口

```go
// cmd/prometheus/main.go
webHandler = web.New(logger, &cfg.web)          // cfg.web 即 web.Options（main.go:879 起填充）
cfg.web.Notifier = notifierManager              // 注入 notifier（alertmanagers API 数据源）
webHandler.SetReady(readyF)                     // WAL 回放完成后置为就绪

// run.Group 中启动（阻塞）：
webHandler.Run(ctx, listener, webConfig)        // listener 来自 --web.listen-address
// 生命周期通道：
webHandler.Reload()                             // /-/reload 触发 main 的 reloader 链
webHandler.Quit()                               // /-/quit 触发优雅退出
```

### 4. 自监控指标（本包暴露的 `web` 指标）

| 指标 | 含义 |
|------|------|
| `prometheus_http_requests_total` | 各路由请求计数（按 code/handler） |
| `prometheus_http_request_duration_seconds` | 请求耗时直方图 |
| `prometheus_http_response_size_bytes` | 响应大小直方图 |
| `prometheus_ready` | 就绪状态 gauge |
| `prometheus_federation_*` | 联邦导出相关计数 |

## 六、关键实现要点

| 关注点 | 说明 |
|--------|------|
| 就绪门控 | `testReady` 包装所有数据类端点；TSDB/WAL 未就绪返回 503，K8s readinessProbe 用 `/-/ready` |
| SPA + 内嵌资源 | React 构建产物 gzip 后 `//go:embed`，单二进制即含 UI；开发态可用 `!builtinassets` 从磁盘读 |
| 热重载链路 | `/-/reload` → `reloadCh` → main 逐个调用 reloader（含 `webHandler.ApplyConfig` 自身），任一失败返回错误详情 |
| Agent 模式裁剪 | `wrapAgent` 包裹的端点在 Agent 下统一返回 422；`/targets`、`/scrape_pools` 等返回 404 |
| API 编码协商 | 请求头 `Accept: application/vnd.google.protobuf` 可获得 protobuf 响应（内部抓取用） |
| TLS/认证 | `--web.config.file` 由 exporter-toolkit 处理（证书、client auth、basic auth、header 鉴权） |
| CORS | `util/httputil.SetCORS` 按 `--web.cors.origin` 正则放行 |
| 前端模块化 | `web/ui/module/*` 的 PromQL 编辑器/语法包独立发布 npm，被 VS Code 等外部工具复用 |
