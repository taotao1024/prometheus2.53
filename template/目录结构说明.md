# Prometheus template 目录结构说明

> 基于 Prometheus v2.53 源码整理。
> `template/` 是 Prometheus 的**模板引擎**：基于 Go `text/template` / `html/template` 扩展，
> 为两类用户提供渲染能力：
> 1. **告警规则模板**——`annotations` 与 `labels` 字段中的 `{{ $labels.xxx }}`、`{{ $value }}` 等表达式；
> 2. **Consoles 控制台模板**——`--web.console.templates` 指定的 HTML 模板页面。
> 它随 `prometheus` 二进制运行，**不是独立服务、无端口**，只是一个被 `rules` 与 `web` 调用的库。

## 一、整体架构（模板渲染链路）

```
 用途 1：告警模板（每次告警求值时渲染）
    rules/alerting.go  AlertingRule.Eval()
        │  template.AlertTemplateData(labels, externalLabels, externalURL, sample)
        │    → 生成模板数据：.Labels / .ExternalLabels / .ExternalURL / .Value / ...
        ▼
    template.NewTemplateExpander(ctx, text, name, data, ts, QueryFunc, externalURL, queryOffset)
        │  Expand()   （panic 恢复保护；missingkey=zero）
        ▼
    渲染出的 annotations / labels 字符串 → 进入 notifier.Alert → Alertmanager

 用途 2：Consoles 控制台（Web UI 页面）
    web/web.go  Handler.consoles()
        │  读取 console 模板文件 + console 库（*.lib）
        ▼
    template.NewTemplateExpander(...).ExpandHTML(templateFiles)
        │  （html/template 自动 HTML 转义 + 可执行 {{ query "..." }} 实时查询）
        ▼
    浏览器渲染 /consoles/*filepath 页面

 用途 3：校验
    ParseTest() —— 只解析不执行，promtool/规则加载时校验模板语法
```

## 二、目录结构总览

```
template/
├── template.go             # ★ 全部实现：Expander、模板数据模型、内置函数表
├── template_test.go        # 渲染/函数/告警数据测试
└── template_amd64_test.go  # amd64 平台相关测试（浮点格式化差异）
```

> 目录无子目录，单文件实现（约 500 行）。

## 三、文件功能说明（`template.go`）

### 3.1 数据模型

| 元素 | 作用 |
|------|------|
| `sample` | 模板中的单条样本：`Labels map[string]string` + `Value` |
| `queryResult` | `[]*sample`——`{{ query "..." }}` 的返回结果 |
| `queryResultByLabelSorter` | 按 `sortByLabel` 指定标签排序结果 |
| `QueryFunc` | `func(ctx, promql string, ts) (promql.Vector, error)`——模板内执行 PromQL 的回调（实际传入 `rules.EngineQueryFunc`） |

### 3.2 Expander（核心展开器）

| 元素 | 作用 |
|------|------|
| `Expander` | 持有模板文本、数据、名称、时间戳、QueryFunc、externalURL、queryOffset、funcMap |
| `NewTemplateExpander(ctx, text, name, data, ts, queryFunc, externalURL, queryOffset)` | 构造展开器并**注册内置函数表**（见 3.3） |
| `Expand()` | 渲染为纯文本（用于告警 annotations/labels）；带 `defer recover()`——模板 panic 只导致该条告警渲染失败，**不会杀死进程**；`Option("missingkey=zero")` |
| `ExpandHTML(templateFiles)` | 渲染 HTML（用于 consoles）：使用 `html/template` 自动转义，支持 `{{ template "head" . }}` 等引用模板库文件 |
| `ParseTest()` | 只解析不执行，校验模板语法合法性 |
| `AlertTemplateData(labels, externalLabels, externalURL, smpl)` | 构造告警模板的数据上下文（`.Labels`、`.ExternalLabels`、`.ExternalURL`、`.Value` 等） |

### 3.3 内置模板函数表（`NewTemplateExpander` 中注册）

| 函数 | 作用 |
|------|------|
| `query "promql"` | 执行 PromQL 即时查询，返回 `queryResult` |
| `first v` / `label "name" s` / `value s` / `strvalue s` | 取第一条结果 / 取样本标签 / 取样本值 / 样本值的字符串形式 |
| `args k1 v1 k2 v2 ...` | 构造 `map[string]interface{}`（向子模板传参） |
| `safeHtml` / `match re str` / `title` | 标记 HTML 安全 / 正则匹配 / 标题化 |
| `sortByLabel "name" v` | 按标签排序结果 |
| `humanize i` | 数字人性化（SI 后缀：`k`/`M`/`G`…） |
| `humanize1024 i` | 二进制单位（`Ki`/`Mi`/`Gi`…，内存等） |
| `humanizeDuration i` | 秒数转可读时长（`1m30s` / `3d 4h`） |
| `humanizePercentage i` | 转百分比（`0.852` → `85.2%`） |
| `humanizeTimestamp i` | Unix 时间戳转 RFC3339 |
| `toTime i` | 数值转 `time.Time` |
| `pathPrefix` / `externalURL` | 取 `--web.route-prefix` / `--web.external-url` |
| `parseDuration d` | duration 字符串（`5m`）转秒数 |

### 3.4 告警模板上下文（`AlertTemplateData` + rules 侧注入的便捷变量）

告警规则里常用变量由 `rules/alerting.go` 以 `defs` 前置定义注入：

| 变量 | 来源 |
|------|------|
| `$labels` / `.Labels` | 告警实例标签（含 rule labels） |
| `$externalLabels` | 全局 external labels |
| `$externalURL` | `--web.external-url` |
| `$value` / `.Value` | 触发告警的样本值 |
| `$valueLabel`（`__value__`） | 同上（原生直方图等新场景） |
| `$alerts` 等聚合变量 | 见 rules/alerting.go 的 defs 注入 |

## 四、归属

- **归属**：`prometheus` 二进制内部的**模板渲染库**，不属于任何独立服务、无端口、无配置文件。
  - 上游使用方：
    - `rules/alerting.go:360-376`——每次告警求值渲染 `annotations`/`labels`；
    - `web/web.go:712-722`——consoles 控制台页面渲染（可执行 `{{ query }}` 实时查询）；
  - 下游产出：发送给 Alertmanager 的告警文本、浏览器可见的 consoles 页面。
- 同样的模板函数族也是 **Alertmanager 模板函数的来源**（Alertmanager 另有扩展）。

## 五、访问入口

### 1. 用户配置入口（模板文本的来源）

**① 告警规则模板**（`rule_files` 中）：

```yaml
groups:
  - name: example
    rules:
      - alert: InstanceDown
        expr: up == 0
        for: 5m
        labels:
          severity: page
          description: '{{ $labels.instance }} of job {{ $labels.job }} has been down for {{ $value }}s'
        annotations:
          summary: 'Instance {{ $labels.instance }} down'
          runbook: '{{ externalURL }}/runbook/down'
```

**② Consoles 控制台模板**（`--web.console.templates` 目录下的 `.html`，可引用 `--web.console.libraries` 的 `.lib`）：

```html
{{ template "head" . }}
{{ template "prom_content_head" . }}
  <h1>Up instances</h1>
  {{ query "up" | sortByLabel "instance" | table }}
{{ template "prom_content_tail" . }}
{{ template "foot" . }}
```

对应启动 flag：

| flag | 作用 |
|------|------|
| `--web.console.templates` | 控制台模板目录（consoles） |
| `--web.console.libraries` | 控制台模板库（`.lib`） |
| `--web.external-url` | `{{ externalURL }}` 的值 |
| `--web.route-prefix` | `{{ pathPrefix }}` 的值 |

### 2. 进程内代码入口

```go
// 告警渲染（rules/alerting.go）
tmplData := template.AlertTemplateData(l, r.externalLabels, r.externalURL, smpl)
tmpl := template.NewTemplateExpander(ctx, text, "__alert_"+r.Name(), tmplData,
    model.Time(timestamp.FromTime(ts)),
    template.QueryFunc(rules.EngineQueryFunc(r.queryEngine, r.queryable)),
    r.externalURL, r.queryOffset)
result := tmpl.Expand()

// consoles 渲染（web/web.go:712）
tmpl := template.NewTemplateExpander(ctx, text, "__console_"+name, data,
    model.Time(timestamp.FromTime(h.options.Now()())),
    template.QueryFunc(rules.EngineQueryFunc(h.queryEngine, h.storage)),
    h.options.ExternalURL, nil)
result, err := tmpl.ExpandHTML(filenames)
```

### 3. HTTP 入口（渲染结果的暴露位置）

| 入口 | 背后渲染 |
|------|----------|
| `GET /api/v1/alerts` / Web UI `/alerts` | 告警的 annotations/labels 模板渲染结果 |
| `GET /consoles/*filepath` | consoles HTML 页面（实时执行 `{{ query }}`） |
| Alertmanager 收到的告警体 | 同告警模板渲染结果 |

### 4. CLI 入口

```bash
promtool check rules rules.yml        # 校验规则文件（含模板语法 ParseTest）
promtool test rules tests.yml         # 规则单元测试（可断言 annotations 渲染结果）
```

## 六、关键实现要点

| 关注点 | 说明 |
|--------|------|
| panic 隔离 | `Expand()` 恢复 panic，只报错不崩溃——坏模板不会杀死 Prometheus 进程 |
| 两套模板引擎 | 告警用 `text/template`（无转义），consoles 用 `html/template`（自动转义），同一函数表 |
| `missingkey=zero` | 访问 map 中不存在的 key 返回零值而非报错 |
| 实时查询 | 模板内 `{{ query "..." }}` 走真正的 PromQL 引擎（consoles 每次刷新页面都执行） |
| `$value` 数字类型 | 样本值可能是 int/float；`convertToFloat` 统一转换，`floatToTime` 支持时间戳函数入参 |
| 错误信息定位 | 模板名带规则名（`__alert_<rule>`）或 console 文件名，便于日志定位 |
