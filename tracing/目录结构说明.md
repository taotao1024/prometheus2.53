# Prometheus tracing 目录结构说明

> 基于 Prometheus v2.53 源码整理。
> `tracing/` 是 Prometheus 的**分布式追踪（OpenTelemetry）管理器**：
> 根据 `prometheus.yml` 的 `tracing` 段构建并安装 OTel TracerProvider，
> 通过 **OTLP（gRPC 或 HTTP）** 把 span 导出到 Jaeger/Tempo 等后端。
> 它随 `prometheus` 二进制运行，**不是独立服务、无监听端口**（自身只是 OTLP 导出**客户端**）。

## 一、整体架构（追踪链路）

```
 ① 配置（prometheus.yml 顶层 tracing 段）
        │
        ▼
 ② tracing.Manager（本包）
    NewManager(logger) → Run()   （注册全局 propagator + 错误处理器，阻塞等待）
    ApplyConfig(cfg)             （热重载：关旧 provider → 按新配置建新的）
        │  buildTracerProvider()
        │    getClient()         按 client_type 选 otlptracegrpc / otlptracehttp
        │    resource.New()      service.name=prometheus, service.version, runtime, telemetry.sdk
        │    TracerProvider      Batcher + 采样（ParentBased + TraceIDRatioBased(sampling_fraction)）
        │  otel.SetTracerProvider(tp)   ← 安装为全局 provider
        ▼
 ③ span 产生点（各组件通过全局 otel.Tracer 埋点）
    promql/engine.go             查询执行 span
    rules/group.go               规则组评估 span
    storage/remote/client.go     远程写/读 HTTP 请求 span
    storage/remote/queue_manager.go  远程写分片 span
    util/stats/query_stats.go    查询计时与 span 关联
        ▼
 ④ 导出（出口）
    POST {endpoint}  OTLP/gRPC 或 OTLP/HTTP  → Jaeger / Tempo / 其它 OTLP 后端
```

**传播协议**：`Run()` 中全局注册 `propagation.TraceContext{}`（W3C `traceparent` 头），
远程读/写与查询的跨进程追踪依赖该头在请求间传递。

## 三、文件功能说明（`tracing.go`）

| 元素 | 作用 |
|------|------|
| `Manager` | 追踪管理器：持有 `config.TracingConfig` 与当前 provider 的 `shutdownFunc` |
| `NewManager(logger)` | 构造管理器 |
| `Run()` | 注册全局文本传播器（`propagation.TraceContext{}`，即 W3C Trace Context）与全局 OTel 错误处理器（错误落到日志），然后阻塞等待 `Stop()` |
| `ApplyConfig(cfg)` | **配置热重载入口**：<br>• 配置未变且无 TLS 配置 → 直接返回（TLS 变化需重启以加载新证书）<br>• 有旧 provider → 先 `shutdownFunc()` 关闭（5s 超时）<br>• `endpoint` 为空 → 视为**禁用追踪**，安装 `noop.NewTracerProvider()`<br>• 否则构建新 provider 并 `otel.SetTracerProvider(tp)` 安装为全局 |
| `Stop()` | 关闭当前 provider 并退出 `Run()` |
| `buildTracerProvider(ctx, cfg)` | 构建 provider 与关闭函数：<br>• resource：`service.name=prometheus`、`service.version=<version>`、进程运行时描述、telemetry SDK 信息（semconv v1.26.0）<br>• `tracesdk.WithBatcher`：批量导出<br>• 采样：`ParentBased(TraceIDRatioBased(sampling_fraction))`——有父 span 时跟随父采样决策，否则按比例 |
| `getClient(cfg)` | 按 `client_type` 构造 OTLP 客户端：<br>• `grpc`：`otlptracegrpc`，支持 endpoint / insecure / TLS / 压缩 / headers / timeout（TLS 证书仅在非 insecure 时生效）<br>• `http`：`otlptracehttp`，支持 endpoint / insecure / gzip 压缩（OTel HTTP 仅支持 gzip）/ headers / timeout / TLS |
| `otelErrHandler` | 把 OTel 内部错误重定向到 Prometheus 日志 |

### 采样语义要点

`sampling_fraction` 只影响**根 span**（无父 trace 的请求）；若上游已带有 traceparent 头，
则跟随上游的采样决策（`ParentBased`），保证同一 trace 全链路一致。

## 四、归属

- **归属**：Prometheus **Server 模式的可观测性组件**，随 `prometheus` 二进制运行；
  不是独立服务、无监听端口；Agent 模式同样编译但默认未启用追踪（无 tracing 配置即 noop）。
  - 上游：`config.TracingConfig`（YAML 解析）；
  - 埋点方：`promql`、`rules`、`storage/remote`（通过全局 `otel.Tracer` 创建 span）；
  - 下游：任何 OTLP 兼容后端（Jaeger、Grafana Tempo、OpenTelemetry Collector 等）。
- 未配置 `tracing.endpoint` 时为**零开销**（noop provider，不产生任何 span）。

## 五、访问入口

### 1. 配置入口（`prometheus.yml` 顶层 `tracing` 段）

```yaml
tracing:
  endpoint: tempo-gateway:4317      # OTLP 后端地址（host:port，gRPC 或 HTTP 端口）
  client_type: grpc                 # grpc（默认）| http
  sampling_fraction: 0.1            # 根 span 采样比例，1.0 = 全采样
  insecure: false                   # true 时 gRPC 走明文
  tls_config:                       # 仅 insecure=false 时生效
    ca_file: ca.cer
    cert_file: client.cer
    key_file: client.key
  headers:                          # 附加到导出请求的头
    x-scope-orgid: my-tenant
  compression: gzip                 # 压缩（HTTP 客户端仅支持 gzip）
  timeout: 10s                      # 单次导出超时
```

对应结构 `config.TracingConfig`（`config/config.go:828`）：
`ClientType` / `Endpoint` / `SamplingFraction` / `Insecure` / `TLSConfig` / `Headers` / `Compression` / `Timeout`。

### 2. 进程内代码入口（`cmd/prometheus/main.go`）

```go
// 1. 创建（main.go:800）
tracingManager = tracing.NewManager(logger)

// 2. 配置热重载（main.go:1005，reloader 名 "tracing"）
reloader: tracingManager.ApplyConfig

// 3. 启动/停止（main.go:1169 / 1173，run.Group actor）
tracingManager.Run()    // 阻塞注册全局 propagator 与错误处理器
tracingManager.Stop()   // 关闭 provider
```

### 3. 出口（Prometheus → OTLP 后端）

| client_type | 实际请求 |
|-------------|----------|
| `grpc`（默认） | OTLP/gRPC 到 `{endpoint}`（默认走 TLS，`insecure: true` 时明文） |
| `http` | OTLP/HTTP `POST {endpoint}/v1/traces` |

### 4. span 产生点（追踪数据的来源，均为全局 otel API）

| 组件 | 位置 | span 内容 |
|------|------|-----------|
| PromQL 引擎 | `promql/engine.go` | 查询求值过程 |
| 规则评估 | `rules/group.go` | 规则组/规则评估（配合 `rules/origin.go` 的来源上下文） |
| 远程写/读客户端 | `storage/remote/client.go` | 到远端的 HTTP 请求 |
| 远程写队列 | `storage/remote/queue_manager.go` | 分片发送 |
| 查询统计 | `util/stats/query_stats.go` | 计时与 trace 关联 |

> 跨进程传播：使用 W3C `traceparent`/`tracestate` 头（`Run()` 中全局注册 `TraceContext{}`）；
> 若要端到端追踪，需上下游（如网关、Alertmanager）同样传播该头。

### 5. 无独立 HTTP/指标入口

本包不暴露任何 HTTP 端点，也没有专属指标；安装/卸载/错误均通过 **Prometheus 日志**观察
（`Tracing provider uninstalled.` / `Successfully installed a new tracer provider.` /
`OpenTelemetry handler returned an error`）。

## 六、注意事项

| 事项 | 说明 |
|------|------|
| 默认关闭 | 不配置 `tracing.endpoint` 即 noop provider，零开销 |
| TLS 变更需重启 provider | `ApplyConfig` 中只要配置含 TLS 就强制重建（保证新证书生效） |
| `sampling_fraction` 语义 | 只对根 span 生效；有上游 trace 时跟随父采样（`ParentBased`） |
| HTTP 客户端压缩限制 | OTel 的 HTTP 导出仅支持 gzip；gRPC 支持更多压缩算法 |
| 优雅关闭超时 | provider shutdown 固定 5s 超时，超时只记日志不阻塞退出 |
| 配置热重载 | `tracing` 段支持 `SIGHUP` / `POST /-/reload` 生效，无需重启进程 |
