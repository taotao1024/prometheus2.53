# Prometheus prompb 目录结构说明

> 基于 Prometheus v2.53 源码整理。
> `prompb/` 是 Prometheus 的 **Protocol Buffers 协议定义包**（`github.com/prometheus/prompb`），
> 定义 **remote write / remote read** 以及 **OTLP 转 Prometheus** 所使用的线格式（wire format）。
> 它本身**不是服务**，不含网络监听逻辑，只是被 `storage/remote/` 等组件引用的序列化协议与生成代码。

## 一、作用与定位（协议在数据流中的位置）

```
远程写（本实例作为发送方）：
  storage/remote/queue_manager.go  ──► codec.go 打包 prompb.WriteRequest ──► client.go ──HTTP──► 远端 /api/v1/write

远程写接收端（本实例作为接收方，需 --enable-feature=remote-write-receiver）：
  远端 ──HTTP──► /api/v1/write ──► storage/remote/write_handler.go 解出 prompb.WriteRequest ──► Appender ──► TSDB

远程读（本实例作为发送方）：
  PromQL / API ──► storage/remote/read.go 构造 prompb.ReadRequest ──HTTP──► 远端 /api/v1/read
  远端返回 prompb.ReadResponse / ChunkedReadResponse ──► 解码为 SeriesSet 参与查询

远程读服务端（本实例作为接收方）：
  远端 ──HTTP──► /api/v1/read ──► storage/remote/read_handler.go ──► 按 prompb.Query 查询本地存储

OTLP：
  /api/v1/otlp/v1/metrics ──► otlptranslator 转换 ──► prompb.WriteRequest ──► Appender
```

## 二、目录结构总览

```
prompb/
├── README.md                    # 说明：编译产物已入库，正常构建无需重新生成
├── buf.yaml                     # Buf（protobuf lint/依赖管理）配置
├── buf.lock                     # Buf 依赖锁文件（gogo/protobuf）
├── remote.proto                 # ★ remote write/read 的 RPC 消息定义（源文件）
├── remote.pb.go                 # remote.proto 的生成代码（gogo/protobuf，勿手改）
├── types.proto                  # ★ 核心数据类型定义（Sample/TimeSeries/Histogram/...）
├── types.pb.go                  # types.proto 的生成代码（gogo/protobuf，勿手改）
├── custom.go                    # 手写辅助方法（Marshal 池化、类型判断等）
└── io/
    └── prometheus/
        └── client/
            ├── metrics.proto    # Prometheus client model 的指标定义（兼容 client_model）
            └── metrics.pb.go    # 其生成代码
```

## 三、文件功能说明

| 文件 | 功能 |
|------|------|
| `README.md` | 说明生成代码已版本化入库；仅当修改了 `.proto` 定义时才需要重新生成（在上级目录执行 `make proto`，依赖 `protoc 3.15.8`） |
| `buf.yaml` | Buf 配置：声明模块名 `buf.build/prometheus/prometheus`、依赖 `buf.build/gogo/protobuf`，并按需豁免部分 lint 规则（枚举前缀、包目录匹配等历史约定） |
| `buf.lock` | Buf 依赖锁定文件，保证生成环境的依赖版本可复现 |
| `remote.proto` | **remote write / remote read 协议定义**：<br>• `WriteRequest`——远程写的请求体（`timeseries` + `metadata`，v2 还含 `symbols` 符号表）<br>• `ReadRequest`——远程读请求（`queries` + `accepted_response_types`）<br>• `ReadResponse`——远程读响应（`results` + `ChunkedReadResponse`/流式 chunk）<br>• `Query`——单个查询（`start_timestamp_ms`/`end_timestamp_ms`/`matchers`/`hints`）<br>• `QueryResult`——查询结果（`timeseries`）<br>• `ChunkedReadResponse`——chunked 远程读的流式响应（`chunked_series` + 序号） |
| `remote.pb.go` | `remote.proto` 由 `protoc-gen-gogofast` 生成的 Go 结构体、`Marshal`/`Unmarshal`/`Size` 等方法（**生成代码，勿手改**） |
| `types.proto` | **核心数据模型**：<br>• `Sample`——单点样本（`value` + `timestamp`）<br>• `TimeSeries`——序列（`labels` + `samples` + `exemplars` + `histograms`）<br>• `Label` / `Labels`——标签与标签集合<br>• `Exemplar`——追踪样例<br>• `Histogram` / `BucketSpan`——原生直方图（含整数/浮点计数、正负桶、span）<br>• `MetricMetadata`——指标元数据（type/metric_family/help/unit）<br>• `LabelMatcher`——标签匹配器（含匹配类型枚举）<br>• `ReadHints`——远程读提示（step、func、分组等）<br>• `Chunk` / `ChunkedSeries`——chunked 远程读的数据单元 |
| `types.pb.go` | `types.proto` 的生成代码（**勿手改**） |
| `custom.go` | **手写扩展方法**（与生成代码分离，便于维护）：<br>• `Sample.T()` / `Sample.V()`——实现 `chunks.Sample` 接口的取值方法<br>• `Histogram.IsFloatHistogram()`——判断直方图计数是否为浮点类型<br>• `ChunkedReadResponse.PooledMarshal()`——使用 `sync.Pool` 复用缓冲区序列化，降低远程读 GC 压力 |
| `io/prometheus/client/metrics.proto` | Prometheus **client model** 的指标定义（与 `prometheus/client_model` 一致的 exposition 格式 protobuf），用于文本/二进制指标格式解析 |
| `io/prometheus/client/metrics.pb.go` | 上述 proto 的生成代码，被 `util/fmtutil`（指标格式化/解析）等引用 |

## 四、协议消息速查

| proto 文件 | 消息 / 枚举 | 用途 |
|------------|-------------|------|
| `remote.proto` | `WriteRequest` | 远程写请求（Timeseries + Metadata + Symbols） |
| `remote.proto` | `ReadRequest` / `ReadResponse` | 远程读请求/响应 |
| `remote.proto` | `Query` / `QueryResult` | 单查询及其结果 |
| `remote.proto` | `ChunkedReadResponse` | chunked 远程读流式分帧响应 |
| `types.proto` | `Sample` / `TimeSeries` | 样本与时间序列 |
| `types.proto` | `Label` / `Labels` / `LabelMatcher` | 标签与匹配器 |
| `types.proto` | `Exemplar` | Exemplar |
| `types.proto` | `Histogram` / `BucketSpan` | 原生直方图 |
| `types.proto` | `MetricMetadata` | 指标元数据 |
| `types.proto` | `ReadHints` | 远程读优化提示 |
| `types.proto` | `Chunk` / `ChunkedSeries` | chunked 传输单元 |

> `ReadRequest.ResponseType` 枚举区分 `SAMPLES`（默认，逐样本）与 `STREAMED_XOR_CHUNKS`（chunked 流式）。

## 五、归属

- **归属**：Prometheus 的**协议定义包**（库），被编译进 `prometheus` 二进制，**不是独立服务、无任何端口**。
- 使用方（本仓库内）：
  - `storage/remote/`：`codec.go`、`client.go`、`queue_manager.go`、`read.go`、`read_handler.go`、`write_handler.go`
  - `storage/remote/otlptranslator/prometheusremotewrite/`：OTLP → remote write 转换
  - `util/fmtutil/`：指标格式解析/格式化（使用 `io/prometheus/client/metrics.proto`）
  - `documentation/examples/remote_storage/remote_storage_adapter/`：示例适配器
- 使用方（生态）：任何实现 remote write/read 的项目都依赖它——Grafana Agent/Alloy、Thanos（receive/sidecar）、Cortex/Mimir、VictoriaMetrics（兼容实现）、Prometheus 各语言 SDK 的 remote write 出口等。

## 六、访问入口

### 1. 网络入口（协议真正落地的地方，均在 Prometheus HTTP 服务上）

| 端点 | 收/发的 prompb 消息 | 开启方式 |
|------|---------------------|----------|
| `POST /api/v1/write` | 接收 `WriteRequest` | `--enable-feature=remote-write-receiver` |
| `POST /api/v1/read` | 接收 `ReadRequest`，返回 `ReadResponse`（可选 chunked 流） | 默认开启 |
| `POST /api/v1/otlp/v1/metrics` | 接收 OTLP，转换为 `WriteRequest` 后写入 | `--enable-feature=otlp-write-receiver` |

### 2. 配置入口（本实例作为客户端主动使用 prompb）

```yaml
# prometheus.yml —— 出口方向
remote_write:
  - url: http://remote:9090/api/v1/write
    protobuf_message: prometheus.WriteRequest   # 选择 message 字段名（v2 协议相关）
    send_exemplars: true
    send_native_histograms: false
remote_read:
  - url: http://remote:9090/api/v1/read
    read_recent: true
```

### 3. 代码入口

```go
// 本仓库内引用 prompb 的典型位置
storage/remote/codec.go:        ToWriteRequest() / DecodeWriteRequest()   // 编码解码 + 符号表
storage/remote/client.go:       Store(ctx, req *prompb.WriteRequest)      // HTTP 发送
storage/remote/write_handler.go: NewWriteHandler() // 解码 prompb.WriteRequest → Appender
storage/remote/read_handler.go:  ToQuery()          // prompb.Query ↔ storage matchers
storage/remote/queue_manager.go: 批量组装 prompb.TimeSeries
```

### 4. 代码生成入口（修改协议时）

```bash
make proto          # → scripts/genproto.sh
# 依赖：protoc 3.15.8、protoc-gen-gogofast、buf（buf.yaml/buf.lock 管理依赖与 lint）
# 产物：remote.pb.go、types.pb.go、io/prometheus/client/metrics.pb.go
```

## 七、兼容性注意事项

| 事项 | 说明 |
|------|------|
| 字段编号不可变 | `.proto` 中已发布字段的 **编号与类型不可修改/删除**，只能新增字段（否则破坏线格式兼容）；废弃字段应标 `reserved` |
| 生成代码勿手改 | `*.pb.go` 全部由 `protoc-gen-gogofast` 生成，直接修改会在下次 `make proto` 时被覆盖；自定义逻辑写进 `custom.go` |
| 协议版本 | remote write 有 1.0（仅 Timeseries/Metadata）与 2.0（带 symbols 符号表 + 自定义 message 名）两种线格式，由 `remote_write.protobuf_message` 与接收端支持情况决定 |
| 无 gRPC 服务定义 | `remote.proto` 中**只有 message、没有 service**，传输层是普通 HTTP + protobuf body（非 gRPC） |
| 流式读取 | `ReadRequest.ResponseType=STREAMED_XOR_CHUNKS` 时响应为多帧 `ChunkedReadResponse`，需要由 `storage/remote/chunked.go` 处理 |
