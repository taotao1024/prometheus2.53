# Prometheus console_libraries 目录结构说明

> 基于 Prometheus v2.53 源码整理。
> `console_libraries/` 是 Prometheus **consoles 控制台模板的公共模板库**：
> 两个 Go `html/template` 的 `.lib` 文件，定义页面骨架、导航菜单、查询下钻等可复用模板，
> 被 `consoles/` 下的页面模板通过 `{{ template "head" . }}`、`{{ template "prom_query_drilldown" ... }}` 引用。
> 由 `web` 服务随 `--web.console.libraries` 加载（默认即本目录），渲染引擎在 `template/` 包。
> **不是服务、无端口**——只是静态模板资源。

## 一、工作机制（与 consoles 的关系）

```
 启动 flag（cmd/prometheus/main.go:387）
    --web.console.libraries=console_libraries   ← 本目录
    --web.console.templates=consoles            ← 页面模板目录
        │
        ▼
 用户访问  GET /consoles/index.html、/consoles/node.html ...
        │
        ▼
 web/web.go  Handler.consoles()
    1. 读取页面模板（consoles/*.html）
    2. Glob 加载本目录所有 *.lib            ← 模板在此并入解析上下文
    3. template.NewTemplateExpander(...).ExpandHTML(filenames)
        ▼
 页面中的 {{ template "head" . }} 等调用命中本库定义的模板 → 渲染返回
```

- 本目录**只提供定义，不提供页面**：没有 `.lib` 文件时 consoles 页面无法渲染（模板未定义错误）；
- 与 `consoles/` 成对出现、成对部署（Docker 中分别为 `/usr/share/prometheus/console_libraries/` 与 `consoles/`）。

## 二、目录结构总览

```
console_libraries/
├── prom.lib       # ★ 通用模板库：页面骨架、查询下钻、时间控件、格式化快捷模板
└── menu.lib       # 导航模板库：顶部 navbar 与左侧菜单
```

> 无子目录，共 2 个文件（文件含非 UTF-8 字节/BOM，某些工具会视为二进制）。

## 三、文件功能说明

### 3.1 `prom.lib` —— 通用模板库（定义约 20 个模板）

**① 页面骨架（consoles 页面的标准结构）**：

| 模板 | 作用 |
|------|------|
| `prom_console_head` | 引入 CSS/JS：Rickshaw（图表）、Bootstrap 4.5.2、`prom_console.css`、d3 v3，均经 `{{ pathPrefix }}` 相对引用 |
| `head` | HTML 头：`<!doctype html>` + `{{ template "prom_console_head" }}` |
| `tail` | 页尾：`</body></html>` |
| `prom_content_head` / `prom_content_tail` | 主内容区容器包裹 |
| `prom_graph_timecontrol` | **时间范围控件**（缩放/平移时间窗的按钮组，依赖 Rickshaw/d3） |

**② 查询与下钻（consoles 的核心能力）**：

| 模板 | 作用 |
|------|------|
| `prom_query_drilldown` | **渲染一个查询结果并链接到 /graph**：`{{ template "prom_query_drilldown" (args "up" "s" "humanize") }}`——参数为 `arg0` 表达式、`arg1` 后缀、`arg2` 渲染模板名；内部执行 `query $expr`，取 `first` 的 `value` 用指定模板格式化，无结果时显示 `-` |
| `prom_path` | 拼接 `/consoles/<Path>?<Params>` 链接（页面间跳转用） |
| `__prom_query_drilldown_noop` | 默认渲染模板（原样输出） |

**③ 数值格式化快捷模板**（包装 `template/` 内置函数，便于 `{{tmpl}}` 传参调用）：

`humanize`、`humanizeNoSmallPrefix`（<1 时不用 k/M 前缀）、`humanize1024`、`humanizeDuration`、`humanizePercentage`、`humanizeTimestamp`、`printf.1f`、`printf.3g`

**④ 右侧状态栏（RHS table）**：

| 模板 | 作用 |
|------|------|
| `prom_right_table_head` / `prom_right_table_tail` | 右侧表格容器（Bootstrap 表格样式） |
| `prom_right_table_job_head` | 传入 job 名，渲染该 job 的 `sum(up)/count(up)` 与 CPU、内存等汇总行（Node Exporter 配套） |

### 3.2 `menu.lib` —— 导航模板库

| 模板 | 作用 |
|------|------|
| `navbar` | 顶部固定导航栏（Bootstrap navbar-dark，品牌区 + 折叠按钮） |
| `menu` | **左侧边栏菜单**：逐项调用 `_menuItem`，默认列出 `index.html.example`（Overview）等 consoles 页面 |
| `_menuItem` | 单个菜单项：`args . "页面文件名" "显示名"`；当前页高亮（`prom_lhs_menu_selected`） |

> 引用链：页面模板（consoles/*.html）→ `head`/`menu`（prom.lib、menu.lib）→
> `prom_console_head`（引入 Rickshaw/Bootstrap）→ `prom_graph_timecontrol`（时间控件）。
> 使用 `navbar`/`menu` 需要页面在合适位置显式 `{{ template "navbar" . }}` / `{{ template "menu" . }}`。

## 四、归属

- **归属**：Prometheus 发行版的**示例静态模板库**（属于 `web` 的 consoles 功能），与 `consoles/` 同属一套：
  - 加载方：`web/web.go` 的 `consoles()` handler（`Glob(librariesPath + "/*.lib")`）；
  - 渲染引擎：`template/`（提供 `query`、`humanize*`、`graphLink` 等函数，本库是其典型调用方）；
  - 发行：tarball/Docker 携带，`--web.console.libraries` 指定路径，**不内嵌二进制**。
- 用户自建控制台时可复制本目录作为起点，或按需删减（例如不用 Rickshaw 图表时只留骨架与格式化模板）。

## 五、访问入口

### 1. 启动配置

| flag | 默认值 | 作用 |
|------|--------|------|
| `--web.console.libraries` | `console_libraries`（`main.go:387`） | 模板库目录，`*.lib` 全部并入每个页面的模板上下文 |
| `--web.console.templates` | `consoles` | 页面模板目录（本库的引用方） |

```bash
./prometheus --web.console.templates=/usr/share/prometheus/consoles \
             --web.console.libraries=/usr/share/prometheus/console_libraries
```

### 2. HTTP 入口（间接受效）

`.lib` 文件**没有独立 URL**——它只影响 `/consoles/*filepath` 页面的渲染结果：

| URL | 与本库的关系 |
|-----|--------------|
| `GET /consoles/*.html` | 页面内 `{{ template "head"/"tail"/"prom_query_drilldown"/"menu"/... }}` 的定义来源 |
| 渲染结果中的 `{{ pathPrefix }}/classic/static/vendor/...` | `prom_console_head` 引入的 CSS/JS 资源 |
| `{{ graphLink $expr }}` 生成的 `/graph?g0.expr=...` 链接 | `prom_query_drilldown` 的下钻目标 |

> 前提：Prometheus 需就绪（`/-/ready` 200），否则 `/consoles/*` 返回 503。

### 3. 进程内代码入口

```go
// web/web.go —— Handler.consoles() 中
libPaths, err := filepath.Glob(filepath.Join(h.options.ConsoleLibrariesPath, "*.lib"))
// → 传给 template.NewTemplateExpander(...).ExpandHTML(filenames)
```

### 4. 自定义入口

```bash
# 复制为自建控制台的模板库基础
cp -r console_libraries/ my-libs/
# 启动时指向自己的目录；页面模板用 {{ template "..." }} 引用其中的定义
./prometheus --web.console.templates=my-consoles --web.console.libraries=my-libs
```

## 六、注意事项

| 事项 | 说明 |
|------|------|
| 缺库则页面报错 | 页面引用的 `head`/`tail` 等模板由本库定义，未配置 `--web.console.libraries` 时 consoles 页面渲染失败 |
| 老技术栈 | 依赖 Bootstrap 4.5、Rickshaw、d3 v3（经 `pathPrefix` 引用内嵌静态资源）；新控制台建议用 React UI 或 Grafana |
| 文件含特殊字节 | `.lib` 文件带 BOM/特殊字符，部分工具会识别为二进制（不影响模板引擎） |
| 模板库全局并入 | 每个 `/consoles/*` 页面都会加载**所有** `.lib`，模板名重复会解析报错，自定义库勿与内置模板重名 |
| `prom_query_drilldown` 参数约定 | 使用 `args` 传参（`arg0/arg1/arg2`），第二个参数是单位后缀，第三个是格式化模板名 |
| 当前页高亮逻辑 | `menu.lib` 的 `_menuItem` 按页面文件名比对（`index.html.example` 等实际文件名），自建页面需同步更新菜单项 |
| 需就绪状态 | 与 consoles 一致，未就绪时端点 503 |
