# Prometheus consoles 目录结构说明

> 基于 Prometheus v2.53 源码整理。
> `consoles/` 是 Prometheus 自带的**控制台模板示例集**（consoles）：
> 一组 Go `html/template` 编写的 HTML 页面，页面内可直接执行 PromQL 查询并渲染表格/图表。
> 由 `web` 服务在 `GET /consoles/*filepath` 暴露，模板渲染逻辑在 `template/` 包
> （`ExpandHTML`），配套的模板库在仓库根 `console_libraries/`。
> **不是服务、无端口**——只是静态模板资源；未启用时（无配置 flag 修改）以默认路径生效。

## 一、工作机制（模板如何变成页面）

```
 prometheus.yml 启动 flag（默认值即本目录与 ../console_libraries）
    --web.console.templates=consoles          ← 本目录（页面模板 .html）
    --web.console.libraries=console_libraries ← 模板库（menu.lib / prom.lib）
        │
        ▼
 用户访问  GET /consoles/index.html、/consoles/node.html ...
        │
        ▼
 web/web.go  Handler.consoles()
    1. 读取模板文件 + Glob 加载 *.lib 模板库
    2. template.NewTemplateExpander(...).ExpandHTML(filenames)
       • html/template 自动转义
       • 页面内 {{ query "promql" }} 实时执行查询（走真正的 PromQL 引擎）
       • {{ humanize1024 ... }}、{{ sortByLabel ... }} 等 template/ 内置函数可用
        ▼
 渲染后的 HTML 返回浏览器（需 Prometheus 处于 ready 状态，否则 503）
```

## 二、目录结构总览

```
consoles/                      # 控制台模板（页面）
├── index.html.example         # 索引页示例（需重命名为 index.html 才会被默认展示）
├── node.html                  # Node Exporter 节点总览列表（入口页）
├── node-overview.html         # 单节点详情页（?instance=<addr>）
├── node-cpu.html              # 单节点 CPU 明细
├── node-disk.html             # 单节点磁盘明细
├── prometheus.html            # Prometheus 自身总览列表
└── prometheus-overview.html   # Prometheus 自身详情页

console_libraries/             # 配套模板库（被页面 {{ template "..." }} 引用）
├── menu.lib                   # 右侧导航菜单模板（prom_right_table_head/tail 等）
└── prom.lib                   # 通用部件：prom_query_drilldown、图形占位、公共头尾
```

> 本目录**无子目录**；与 `console_libraries/` 成对出现（页面模板 + 可复用库）。

## 三、文件功能说明

| 文件 | 功能 | 关键模板用法 |
|------|------|--------------|
| `index.html.example` | **索引页示例**：说明这些示例依赖的 job 标签约定（Node Exporter → `job="node"`、Prometheus → `job="prometheus"`）。文件名带 `.example` 后缀，**不会**被 `/consoles/` 目录索引默认命中，复制为 `index.html` 即可启用 | 纯模板引用 `head`/`prom_right_table_*`/`prom_content_*`/`tail` |
| `node.html` | **节点列表页**：遍历 `up{job='node'}`（`{{ range query ... \| sortByLabel "instance" }}`），展示每个节点的存活、CPU 使用率、可用内存；点击进入单节点页 | `query` + `sortByLabel`、`prom_query_drilldown`（带链接的查询结果）、`reReplaceAll`（从 instance 提取主机名）、`humanize1024` |
| `node-overview.html` | **单节点详情**：按 `?instance=` 参数展示 CPU/内存/网络/文件系统等关键指标的趋势图（GraphLink） | `param` 读 URL 参数、`prom_graph` 系列模板 |
| `node-cpu.html` | 单节点 **CPU 明细**：各 mode（user/system/iowait…）的 CPU 时间率 | `query` + `prom_query_drilldown` |
| `node-disk.html` | 单节点 **磁盘明细**：各挂载点的空间与 I/O 指标 | 同上 |
| `prometheus.html` | **Prometheus 自身列表页**：多实例 Prometheus 部署时的入口（`up{job='prometheus'}`） | 同 node.html |
| `prometheus-overview.html` | **Prometheus 自身详情**：抓取目标数、规则、内存/GC、WAL、查询延迟等自监控指标 | `query` + 图表模板 |

> 模板库（`console_libraries/prom.lib`、`menu.lib`）提供：`head`/`tail` 页面骨架、
> `prom_right_table_head/tail` 右侧菜单、`prom_query_drilldown expr [unit] [format]`
> （渲染一个可点击下钻的查询结果）、`prom_graph`（Graph Link 图表）等。

## 四、归属

- **归属**：Prometheus 发行版的**示例静态模板资源**（属于 `web` 的 consoles 功能），编译期**不进二进制**（运行时从磁盘读取，故部署时需保证目录存在——这也是 tarball 包含它们的原因）。
  - 渲染引擎：`template/`（`ExpandHTML`，函数表见其文档）；
  - HTTP 暴露：`web/web.go` 的 `consoles()` handler；
  - Docker/tarball 发行：Dockerfile 中 `COPY consoles/ /usr/share/prometheus/consoles/`、`COPY console_libraries/ /usr/share/prometheus/console_libraries/`，并把 `--web.console.*` 指向这些路径。
- 示例预期与 **Node Exporter**（`job="node"`）、Prometheus 自监控（`job="prometheus"`）配合使用。

## 五、访问入口

### 1. 启动配置（flag，`cmd/prometheus/main.go:383`）

| flag | 默认值 | 作用 |
|------|--------|------|
| `--web.console.templates` | `consoles` | 控制台模板目录（即本目录），暴露在 `/consoles` |
| `--web.console.libraries` | `console_libraries` | 模板库目录（`.lib` 文件） |

```bash
./prometheus --web.console.templates=/usr/share/prometheus/consoles \
             --web.console.libraries=/usr/share/prometheus/console_libraries
```

### 2. HTTP 入口（页面）

| URL | 内容 |
|-----|------|
| `GET /consoles/index.html` | 示例索引页（需先复制 `index.html.example` → `index.html`） |
| `GET /consoles/node.html` | 节点列表 |
| `GET /consoles/node-overview.html?instance=host:9100` | 单节点详情 |
| `GET /consoles/node-cpu.html?instance=...` / `node-disk.html?instance=...` | CPU / 磁盘明细 |
| `GET /consoles/prometheus.html` / `prometheus-overview.html?instance=...` | Prometheus 自监控 |
| Web UI `/status` 页面中的 Consoles 链接 | UI 会列出可用的 consoles 页面 |

> 前提条件：Prometheus 必须**就绪**（`/-/ready` 为 200），否则 consoles 端点返回 503。

### 3. 进程内代码入口

```go
// web/web.go —— consoles 请求处理
router.Get("/consoles/*filepath", readyf(h.consoles))

func (h *Handler) consoles(w http.ResponseWriter, r *http.Request) {
    // 1. 路径安全校验（禁止目录穿越）
    // 2. 读取模板文件
    // 3. Glob 加载 --web.console.libraries/*.lib
    // 4. template.NewTemplateExpander(...).ExpandHTML(filenames)  ← template/ 包
}
```

### 4. 自定义入口（用户自己的控制台）

```bash
# 复制示例为起点，或自建目录
cp -r consoles/ my-consoles/
# 启动时指向自己的目录即可；模板内可用 template/ 的全部函数：
# query、sortByLabel、humanize*、prom_query_drilldown、reReplaceAll、param、args...
./prometheus --web.console.templates=my-consoles --web.console.libraries=my-libs
```

## 六、注意事项

| 事项 | 说明 |
|------|------|
| `index.html.example` 需重命名 | 示例文件刻意带 `.example` 后缀，避免与用户自建 `index.html` 冲突 |
| 依赖 job 标签约定 | 示例页面查询写死了 `job='node'` / `job='prometheus'`，抓取配置需匹配（或自行改模板） |
| 模板从磁盘读取 | consoles **不内嵌进二进制**；容器/自定义部署需 COPY 目录并设置 flag |
| 页面可执行实时查询 | 每次刷新都会跑 `{{ query }}`，大量并发访问会消耗查询资源 |
| HTML 自动转义 | 经 `html/template` 渲染，模板内插入原生 HTML 需 `safeHtml` |
| 需就绪状态 | 未就绪（WAL 回放中）访问 `/consoles/*` 返回 503 |
| 与 Grafana 的关系 | consoles 是 Prometheus 原生的轻量仪表盘方案；Grafana 是功能更强的替代品，但 consoles 无需额外部署 |
