# Prometheus config 目录结构说明

> 基于 Prometheus v2.53 源码整理。
> `config/` 是 Prometheus 的**配置模型与加载器**：定义 `prometheus.yml` 的全部结构体
> （`Config`/`GlobalConfig`/`ScrapeConfig`/`RemoteWriteConfig`...），负责 YAML 解析、
> 严格校验、默认值填充、相对路径展开与 Agent 模式校验。
> 它随 `prometheus` / `promtool` 二进制运行，**不是服务、无端口**，
> 是所有组件配置（scrape、storage、remote、tracing、alerting...）的**单一事实来源**。

## 一、整体架构（配置生命周期）

```
 prometheus.yml（用户配置）
        │
        ▼
 ① 加载：config.LoadFile(filename, agentMode, expandExternalLabels, logger)
    • yaml.UnmarshalStrict（未知字段直接报错）
    • 默认值填充（DefaultConfig / DefaultGlobalConfig / DefaultScrapeConfig ...）
    • SetDirectory(dir)：所有相对文件路径（ca_file、rule_files...）拼接 --config.file 所在目录
    • Agent 模式校验（禁用 rules/alerting/remote_read 等）
    • expandExternalLabels：external_labels 中 {{ }} 模板展开
        │
        ▼
 ② 启动：main.go 调 LoadFile 两次
    main.go:589  启动早期（NopLogger，失败立即退出并打印路径）
    main.go:1512 reloadConfig()（正式加载，随后分发给各 reloader）
        │
        ▼
 ③ 分发：reloadConfig() → 各组件 ApplyConfig(*Config)
    scrapeManager / rules / notifier / webHandler / remoteStorage / tracingManager ...
        │
        ▼
 ④ 热重载：SIGHUP / POST /-/reload → /-/reload 端点 → webHandler.Reload() → 同上
```

## 二、目录结构总览

```
config/
├── config.go                # ★ 全部配置模型与加载逻辑（单文件约 1250 行）
├── config_test.go           # 主测试（testdata 下大量 YAML 用例）
├── config_default_test.go   # 校验 Default* 常量与 YAML 反序列化默认值一致
├── config_windows_test.go   # Windows 平台路径/文件权限相关测试
└── testdata/                # 测试配置集（100+ YAML：合法/非法/各类组件组合）
```

> 无子目录包（`testdata` 仅测试数据）。

## 三、文件功能说明（`config.go`）

### 3.1 加载入口

| 函数 | 作用 |
|------|------|
| `Load(s, expandExternalLabels, logger)` | 解析 YAML 字符串 → `*Config`（严格模式、默认值、校验） |
| `LoadFile(filename, agentMode, expandExternalLabels, logger)` | 读文件 → `Load`；先 `SetDirectory` 展开相对路径；Agent 模式下校验禁用项；返回**已脱敏前**的结构（`String()` 输出时脱敏） |
| `filePath` / `fileErr` / `getGoGCEnv` | 相对路径处理与运行时环境读取辅助 |

### 3.2 顶层配置模型（`Config`，yaml 根结构）

| 字段 | yaml 键 | 类型与说明 |
|------|---------|-----------|
| `GlobalConfig` | `global` | 全局默认（见下） |
| `AlertingConfig` | `alerting` | Alertmanager 列表 + `alert_relabel_configs` |
| `RuleFiles` | `rule_files` | 规则文件（相对路径经 SetDirectory 展开） |
| `ScrapeConfigs` | `scrape_configs` | 抓取配置列表 |
| `StorageConfig` | `storage` | `tsdb:`（`out_of_order_time_window` 等）+ `exemplars: max_exemplars` |
| `TracingConfig` | `tracing` | OpenTelemetry 导出配置 |
| `RemoteWriteConfigs` | `remote_write` | 远程写列表 |
| `RemoteReadConfigs` | `remote_read` | 远程读列表 |
| `RuntimeConfig` | `runtime` | Go 运行时调优：`gogc` / `gomemlimit` / `gomaxprocs` |

其它方法：`SetDirectory`（递归展开文件路径）、`String()`（**脱敏输出**，密码/token 打码；`/config` 页与 `/api/v1/status/config` 返回它）、`UnmarshalYAML`（严格校验 + 校验 rule_files 存在性等）。

### 3.3 各子配置模型

| 模型 | yaml 键 | 关键字段 |
|------|---------|----------|
| `GlobalConfig` | `global` | `scrape_interval`、`scrape_timeout`、`scrape_protocols`、`scrape_classic_histograms`、`external_labels`、`external_url`、`body_size_limit`、`sample_limit`、`target_limit`、`label_limit`、`label_name_length_limit`、`label_value_length_limit`、`keep_dropped_targets`、`query_log_file` |
| `ScrapeConfig` | `scrape_configs[]` | `job_name`（必填）、`honor_labels`、`honor_timestamps`、`track_timestamps_staleness`、`params`、`scheme`、`metrics_path`、以上各 limit 的覆盖、`metric_relabel_configs`、认证（`authorization`/`basic_auth`/`oauth2`）、`tls_config`、`proxy_url`、`follow_redirects`、`http_headers`、内嵌 **SD 配置**（`static_configs` + 各 `*_sd_configs`，通过 discovery 注册表反序列化）、`sample_limit` 校验等（`Validate` 检查 timeout ≤ interval、job_name 唯一性等在 Config 层） |
| `AlertingConfig` | `alerting` | `alert_relabel_configs`（[]`relabel.Config`）、`alertmanager_configs`（[]`AlertmanagerConfig`） |
| `AlertmanagerConfig` | `alertmanagers[]` | SD 配置、`scheme`、`path_prefix`、`timeout`、`api_version`（`v1`/`v2`，默认 v2）、`tls_config`、`proxy_url`、认证 |
| `RemoteWriteConfig` | `remote_write[]` | `url`（必填）、`name`、`remote_timeout`、`headers`、`write_relabel_configs`、`send_exemplars`、`send_native_histograms`、`queue_config`、`metadata_config`、`sigv4`、`azuread`、`oauth2`、`tls_config`、`proxy_url` |
| `QueueConfig` | `queue_config` | `capacity`、`min_shards`、`max_shards`、`max_samples_per_send`、`batch_send_deadline`、`min_backoff`、`max_backoff`、`retry_on_failure`、`sample_age_limit` |
| `MetadataConfig` | `metadata_config` | `send`、`send_interval` |
| `RemoteReadConfig` | `remote_read[]` | `url`、`remote_timeout`、`read_recent`、`name`、`required_matchers`、`filter_external_labels`、认证/TLS/代理 |
| `StorageConfig` / `TSDBConfig` | `storage` | `tsdb.out_of_order_time_window`（乱序窗口）、`exemplars.max_exemplars` |
| `TracingConfig` | `tracing` | `endpoint`、`client_type`（grpc/http）、`sampling_fraction`、`insecure`、`tls_config`、`headers`（`validateHeadersForTracing` 校验保留头）、`compression`、`timeout` |
| `ExemplarsConfig` | `exemplars` | `max_exemplars` |
| `RuntimeConfig` | `runtime` | `gogc`、`gomemlimit`、`gomaxprocs` |

### 3.4 校验辅助

| 函数 | 作用 |
|------|------|
| `validateHeaders` / `validateHeadersForTracing` | 禁止请求头中出现 `Authorization` 等保留键 |
| `validateAcceptScrapeProtocols` / `ScrapeProtocol.Validate` | 校验 `scrape_protocols` 合法值（PrometheusProto/OpenMetricsText/PrometheusText） |
| `checkStaticTargets` / `CheckTargetAddress` | 校验 static targets 地址格式（拒绝空/非法地址） |
| `AlertmanagerAPIVersion` / `TracingClientType` / `ScrapeProtocol` 的 `UnmarshalYAML` | 枚举值解析 |

> 注意：**`relabel.Config`、SD 各 `Config`、认证配置**定义在别的包（`model/relabel`、`discovery/*`、
> `common/config`），`config.go` 只是组合引用——这是配置可扩展性（`plugins/` 注册机制）的基础。

## 四、归属

- **归属**：`prometheus` 与 `promtool` 共用的**配置层库**，不是服务、无端口、无独立进程。
  - 唯一加载入口在 `cmd/prometheus/main.go`（`LoadFile`），热重载由 `/-/reload`/SIGHUP 触发；
  - `promtool check config` 复用 `LoadFile` 做配置体检；
  - `String()` 的脱敏输出是 `/config` 与 `/api/v1/status/config` 的数据源。
- 依赖方向：`config` → `discovery`（SD 配置）/`model/relabel`/`common/config`；
  反向：所有组件接收 `*Config` 的引用并在 `ApplyConfig` 中抽取自己关心的部分。

## 五、访问入口

### 1. 配置入口（本包就是入口：`--config.file`）

```bash
prometheus --config.file=prometheus.yml          # 默认 prometheus.yml
promtool check config prometheus.yml             # 校验（语法/表达式/模板/路径/SD）
promtool check web-config web-config.yml         # 校验 --web.config.file（不在本包）
```

最小配置示例（覆盖全部顶层键）：

```yaml
global:
  scrape_interval: 15s
  scrape_timeout: 10s
  external_labels: { cluster: prod }

runtime:
  gomaxprocs: 4

storage:
  tsdb:
    out_of_order_time_window: 5m
  exemplars:
    max_exemplars: 100000

tracing:
  endpoint: tempo:4317

rule_files: [rules/*.yml]

scrape_configs:
  - job_name: node
    static_configs: [{ targets: ['localhost:9100'] }]

alerting:
  alertmanagers:
    - static_configs: [{ targets: ['alertmanager:9093'] }]

remote_write:
  - url: http://remote:1234/api/v1/write
    queue_config: { max_samples_per_send: 2000 }

remote_read:
  - url: http://remote:1234/api/v1/read
```

### 2. 进程内代码入口

```go
// cmd/prometheus/main.go
// ① 启动早期加载（main.go:589，失败直接退出）
cfgFile, err = config.LoadFile(cfg.configFile, agentMode, false, log.NewNopLogger())

// ② 热重载加载（main.go:1512，reloadConfig 内）
conf, err := config.LoadFile(filename, agentMode, expandExternalLabels, logger)
// 随后 diff 比较 + 逐个 reloader 分发（scrape_sd、notify_sd、scrape、rules、web、remote、tracing...）
```

### 3. HTTP 入口（配置的展示端）

| 端点 | 说明 |
|------|------|
| `GET /config`（Web UI） | 展示 `Config.String()` 脱敏后的 YAML |
| `GET /api/v1/status/config` | 同上，`{"yaml": "...", "status": "success"}` |
| `POST /-/reload` / `SIGHUP` | 触发重新 `LoadFile` 与全组件热重载 |

### 4. CLI 入口

| 命令 | 用途 |
|------|------|
| `promtool check config <file>` | 语法/语义校验 + 规则文件 + 单元测试文件扫描 |
| `promtool check service-discovery` | 复用 `ScrapeConfig` 的 SD + relabel 预演 |
| `promtool test rules` | 规则测试（读取配置解析部分字段） |

## 六、关键实现要点

| 关注点 | 说明 |
|--------|------|
| 严格解析 | `UnmarshalStrict`：拼写错误的配置键**启动即报错**（防呆核心） |
| 默认值机制 | 每个模型的 `UnmarshalYAML` 先填 `Default*` 再覆盖；`config_default_test.go` 保证默认值与文档一致 |
| 相对路径 | `SetDirectory` 把 `rule_files`、证书、SD 文件等相对路径锚定到 `--config.file` 所在目录 |
| Agent 模式校验 | `LoadFile(agentMode)` 拒绝 `rule_files`、`alerting`、`remote_read` 等仅 Server 可用的配置 |
| 脱敏 | `String()` 对 URL 中的用户信息、`authorization`/`sigv4`/`oauth2` 密钥打码后输出 |
| 热重载 diff | main 用 `yaml.Marshal` 序列化比较新旧配置，未变化的部分 reloader 快速跳过 |
| 可扩展 SD | `scrape_configs`/`alertmanagers`/`remote_write` 内嵌 SD 配置依赖 `discovery` 注册表（`plugins/` 空导入），未注册的 SD 类型无法解析 |
| 保留头校验 | tracing/remote_write 的 `headers` 与认证字段互斥，配置了保留键直接报错 |
