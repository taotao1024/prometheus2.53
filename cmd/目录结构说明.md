# Prometheus cmd 目录结构说明

> 基于 Prometheus v2.53 源码整理。
> `cmd/` 是仓库**仅有的两个可执行入口**：
> - `cmd/prometheus/` —— Prometheus **服务端主程序**（把 discovery/scrape/storage/promql/rules/notifier/web 全部组装起来）；
> - `cmd/promtool/` —— Prometheus **命令行工具**（配置/规则校验、查询、TSDB 运维、数据回填、规则单测、调试采集）。
> 构建产物即 `prometheus` 与 `promtool` 两个二进制；`cmd/` 本身不含业务逻辑，只做**装配与 CLI 编排**。

## 一、整体架构

```
go build ./cmd/prometheus  →  prometheus（服务端二进制）
    main.go
      ├─ flag 解析（kingpin，全部 --storage.tsdb.* / --web.* / --query.* ...）
      ├─ config.LoadFile                     （config 包）
      ├─ runtime 调优（GOMAXPROCS/GOGC/limit）
      ├─ 组件装配（见下「组装清单」）：
      │    remote storage(fanout) / scrape / discovery / notifier / rules / promql / web / tracing
      └─ run.Group 协程编排：DB.Open、webHandler.Run、reloader 链、TERM/HUP 信号、目录监听

go build ./cmd/promtool  →  promtool（CLI 工具）
    main.go
      ├─ kingpin 子命令树：check / query / debug / test / tsdb / promql / sd ...
      └─ 各子命令实现于同目录按域拆分的文件（tsdb.go、rules.go、unittest.go ...）
```

### 组件组装清单（`cmd/prometheus/main.go` 中的关键行号）

| 组件 | 创建 | Run/Stop | 热重载 reloader |
|------|------|----------|-----------------|
| 远程存储 | `remote.NewStorage`（main.go:709）+ `storage.NewFanout` | QueueManager 随 fanout | `ApplyConfig` |
| Notifier | `notifier.NewManager`（main.go:718） | `Run`/`Stop`（1400/1405） | `notify_sd` SD 同步 |
| Web | `web.New`（main.go:879） | `webHandler.Run`（1375） | `webHandler.ApplyConfig` |
| PromQL 引擎 | `promql.NewEngine`（main.go:830 起） | 随查询 | — |
| 规则 | `rules.NewManager`（main.go:847） | `ruleManager.Run` | `rules.Update` |
| 抓取 | `scrape.NewManager`（main.go:788） | `scrapeManager.Run`（1143） | `scrape.ApplyConfig` |
| 服务发现 | `discovery.NewManager` ×2（scrape 侧 866 / notify 侧 872） | `Run(SyncCh)` | scrape_sd / notify_sd |
| Tracing | `tracing.NewManager`（main.go:800） | `Run`/`Stop`（1169/1173） | `ApplyConfig` |
| TSDB | `tsdb.Open`（main.go:1432） | 随进程 | — |
| 配置 | `config.LoadFile`（589 启动 / 1512 重载） | — | 比对后逐个分发 |

## 三、`cmd/prometheus/` 功能说明

| 文件 | 作用 |
|------|------|
| `main.go` | **主程序**：<br>• flag 定义（约 60 个：`--config.file`、`--storage.tsdb.path/retention/agent`、`--web.*`、`--query.*`、`--scrape.*`、`--rules.*`、`--alertmanager.*`、`--enable-feature`、`--log.*`...）<br>• Agent/Server 模式分支（`--agent` 改变存储与禁用组件）<br>• 早期配置校验（main.go:589 `LoadFile`，失败打印绝对路径退出）<br>• Go runtime 调优（`config.RuntimeConfig` → GOMAXPROCS/GOGC/GOMEMLIMIT，文件描述符上限检查）<br>• 组件创建与 reloader 注册表（`reloaders` 切片，按依赖顺序：remote→scrape_sd→scrape→notify_sd→notify→rules→web→tracing）<br>• `run.Group` 协程编排：TSDB 打开、web 服务、SD/抓取/规则/通知循环、`TERM`/`INT` 优雅退出、`SIGHUP`/配置目录监听触发重载<br>• WAL 回放进度上报（`/status/walreplay` 数据源）、就绪置位 `webHandler.SetReady` |
| `prometheus.yml` | 仓库内默认示例配置（纯注释文档，启动不带 `--config.file` 时若不存在会报错，此文件供参考） |
| 测试文件 | 启动/重载/最小配置、Unix 信号与目录监听、查询日志行为 |

**热重载链路（main.go reloadConfig）**：

```
SIGHUP / POST /-/reload / 配置文件所在目录事件
  → reloadConfig(filename)
      → config.LoadFile（1512）
      → 与当前配置序列化 diff（未变的 reloader 跳过）
      → 依次执行 reloader（任一失败回滚报错）
      → 成功：configSuccess 计数、web 层更新
```

## 四、`cmd/promtool/` 功能说明

### 4.1 子命令树（`main.go`，kingpin）

```
promtool
├── check ──────────────── 配置与资源校验
│   ├── config <file>           # prometheus.yml 全量校验（语法/规则文件/SD）
│   ├── rules <file...>         # 规则文件校验（rulefmt + 模板）
│   ├── web-config <file>       # --web.config.file 校验
│   ├── config-files <dir>      # 目录下全部配置
│   ├── healthy / ready <url>   # 远端实例存活/就绪检查
│   └── service-discovery <job> # SD + relabel 预演（sd.go）
├── query ──────────────── 远端查询
│   ├── instant <server> <expr> # 即时查询
│   ├── range <server> <expr>   # 区间查询
│   ├── labels <server>         # 标签名/值
│   ├── series <server>         # series 匹配
│   └── analyze <server> <expr> # 指标使用模式分析（analyze.go）
├── debug ──────────────── 调试信息采集
│   ├── pprof <url> <item>      # 拉取 pprof profile
│   ├── metrics <url>           # 拉取 /metrics
│   └── all <url>               # 全部打包（archive.go 的 tar.gz 写入器）
├── test ───────────────── 测试
│   └── rules <file...>         # 规则单元测试（unittest.go，promqltest 框架）
├── tsdb ───────────────── TSDB 运维
│   ├── list <db path>          # 列出块
│   ├── dump <db path>          # 导出样本为文本/OpenMetrics
│   ├── analyze <db path>       # 基数/churn/压缩效率分析（analyze.go/tsdb.go）
│   ├── bench write             # 写入基准（默认 20kseries.json）
│   └── create-blocks-from ──── 历史数据回填
│       ├── openmetrics <input> # 文本/OpenMetrics 文件 → TSDB 块（backfill.go）
│       └── rules <start> <end> # 为新记录规则回填历史数据（rules.go）
├── push metrics <url> <files...>   # 文本格式指标推送（remote write，metrics.go）
└── promql format/labels modify/delete   # PromQL 文本处理
```

### 4.2 实现文件

| 文件 | 职责 | 对应命令 |
|------|------|----------|
| `main.go` | 子命令树定义、`Check*` 系列函数（config/rules/web-config/healthy/ready） | `check` |
| `tsdb.go` | `listBlocks`/`dumpSamples`/`analyzeBlock`/`benchWrite`/`checkErr` | `tsdb list/dump/analyze/bench` |
| `backfill.go` | 回填引擎：解析输入 → 计算时间边界 → 按块时长切分 `createBlocks` → 直接写 TSDB 块目录 | `tsdb create-blocks-from openmetrics` |
| `rules.go` | 按历史数据评估**记录规则**并生成块（依赖 promql 引擎 + tsdb.Appender） | `tsdb create-blocks-from rules` |
| `unittest.go` | 规则单测运行器：`group_order`/`interval`/`input_series`/`alert_rule_test`/`promql_expr_test` 语法 | `test rules` |
| `query.go` | HTTP 客户端封装：instant/range/labels/series | `query` |
| `analyze.go` | 发送 `stats=all` 查询并分析指标使用模式（基数/TSDB 状态查询） | `query analyze` |
| `debug.go` | 抓取远端 `/debug/pprof/*`、`/metrics` | `debug` |
| `metrics.go` | `PushMetrics`：解析文本格式 → `prompb.WriteRequest` → `remote.Client` 推送（配合 `fmtutil`） | `push metrics` |
| `sd.go` | 复用 `scrape.TargetsFromGroup` 预演 SD + relabel 结果 | `check service-discovery` |
| `archive.go` | `newTarGzFileWriter`：debug 信息打包为 tar.gz | `debug all` |

## 五、归属

- **归属**：两个**可执行程序入口**（`package main`），是前面所有包文档所述组件的**装配层**：
  - `prometheus` —— Server/Agent 模式的完整监控服务端；
  - `promtool` —— 独立 CLI 工具，无端口，处理完即退出；
  - 二者共用同一份 `github.com/prometheus/prometheus` 模块代码；`promtool` 大量复用
    `config`/`rulefmt`/`scrape`/`promqltest`/`tsdb`/`fmtutil` 等库（CI 与运维的一致性来源）。
- Docker 镜像同时包含两个二进制（`prometheus` 为主进程，`promtool` 可 `docker run ... promtool ...` 调用）。

## 六、访问入口

### 1. 命令行入口（最直接）

```bash
# 服务端
prometheus --config.file=prometheus.yml --storage.tsdb.path=data/ --web.listen-address=:9090
prometheus --agent            # Agent 模式
prometheus --version

# 工具
promtool check config prometheus.yml
promtool check rules rules/*.yml
promtool test rules rules_test.yml
promtool tsdb analyze data/
promtool tsdb dump data/ > dump.txt
promtool tsdb create-blocks-from openmetrics metrics.om data/
promtool tsdb create-blocks-from rules 2024-01-01T00:00:00Z 2024-02-01T00:00:00Z old.yml data/
promtool query instant http://localhost:9090 'up'
promtool debug all http://localhost:9090
```

完整 CLI 文档由 `documentcli` 生成（`prometheus --write-documentation` / `promtool --write-documentation`），
存于 `docs/command-line/`。

### 2. 运行时入口（`prometheus` 启动后）

| 入口 | 提供方 |
|------|--------|
| `:9090` 全部 HTTP 端点（UI/API/metrics/federate/生命周期） | `web`（见其文档） |
| `SIGHUP` / `POST /-/reload` 热重载 | main.go reloadConfig |
| `SIGTERM`/`SIGINT` 优雅退出 | run.Group 中断 |

### 3. 构建入口

```bash
make build            # 编译两个二进制（依赖 plugins/assets 前置目标）
make common-build     # 仅编译（promu）
go build ./cmd/prometheus ./cmd/promtool   # 直接 go build
```

### 4. 测试入口

```bash
go test ./cmd/prometheus   # 启动/重载/信号/查询日志
go test ./cmd/promtool     # 各子命令 + testdata 用例
```

## 六、关键实现要点

| 关注点 | 说明 |
|--------|------|
| 单文件装配 | `prometheus/main.go` 是全部组件的组装点；其它包都可通过其行号定位（前面各份文档已引用） |
| reloader 顺序敏感 | 热重载按依赖顺序执行（SD → scrape/notifier → rules → web），避免旧目标先失效 |
| Agent 模式分支 | `--agent` 下：WAL-only 存储、禁用 rules/alerting/remote_read、`--config.file` 校验随之收紧 |
| 优雅退出 | run.Group 按 LIFO 顺序关闭：先停 web/SD → 再关存储 flush |
| 启动自检 | 端口占用自检（`webHandler.Listener` 预探）、文件描述符上限告警、目录可写检查 |
| promtool 回填 | `create-blocks-from` 直接生成 TSDB 块目录，需停实例或另挂只读数据目录使用 |
| kingpin 文档化 | `documentcli.GenerateMarkdown` 从同一命令树生成 `docs/command-line/*.md`，CLI 与文档永不漂移 |
| 无逻辑泄漏原则 | 业务逻辑全部在库包，`cmd/` 仅编排——便于库复用与测试 |
